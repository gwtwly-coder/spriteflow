# SpriteFlow M1 产品需求文档（PRD）

> 文档版本：M1 v1.0  
> 产品角色：产品经理  
> 事实来源：`docs/technical-design.md`，其中第 9 节 M1 里程碑为范围裁决依据  
> UI 文案来源：`docs/copy-m1.md`

## 1. 产品定义

SpriteFlow M1 是一款面向 2D 游戏个人开发者的纯前端 Web 工具。它接收已经带透明背景的单张 sprite sheet，在浏览器内自动检测帧，让用户快速修正检测框，并导出 Phaser 3 或 Godot 4 可用的素材。

M1 要验证的不是“所有图片都能全自动切好”，而是这条最短闭环是否成立：

**透明底图片 → 网格/连通域检测 → 人工审校 → Phaser/Godot 导出。**

产品承诺是“10 秒从合格样例到可导出结果”，不是“全自动万能”。当检测没有把握时，产品必须明确降级，让用户用手动网格或手动画框完成工作，不能静默输出看似成功的错误结果。

### 1.1 M1 范围裁决

- 第 9 节规定的 M1 范围只有：应用骨架、透明底输入、策略 A/B 检测、审校编辑器、Phaser/Godot 导出、黄金测试集 20 例。
- “透明底输入”在 M1 中解释为单张、可解码且确实含透明像素的 PNG 或 WebP。JPG、不透明 PNG/WebP、GIF/APNG、视频与 ZIP 不属于 M1。
- “策略 A/B”分别指网格检测与连通域检测。尺寸聚类不作为 M1 的独立用户能力。
- 第 4 节的批量锚点/缩放与第 9 节 M3 的锚点对齐/尺寸归一冲突时，以里程碑为准：M1 不包含这些能力。
- Godot M1 采用第 5 节优先方案：帧序列 ZIP 与 `build_spriteframes.gd`；不包含实验性 `.tres` 直出。
- M3 所称“中英双语打磨”不阻止 M1 提供基础中英双语界面；M1 文案以可用、完整为标准，后续再做语气与本地化打磨。

## 2. 目标用户

### 2.1 核心画像

核心用户是国内外的 vibe coder：用 Cursor、Claude 等工具写 Phaser/Godot 游戏，用 ChatGPT、Midjourney 或素材包得到角色图，但不是专业美术或图形工具用户。

- **身份**：独立开发者、Game Jam 参与者、下班后做游戏的程序员、小型团队里的全栈开发者。
- **技能结构**：会写代码、会调用引擎 API，能看懂 JSON 和文件结构；不熟悉 Photoshop、Aseprite、TexturePacker 的完整工作流。
- **典型输入**：透明底规整网格表、透明底单行动画条、透明底散排或间距不齐的角色帧。
- **当前做法**：手工量坐标、逐帧裁图、反复调整 JSON，或在多个工具之间来回导入导出。
- **核心痛点**：不是缺一张图，而是缺少把图变成引擎可直接使用素材的最后一公里；最讨厌坐标、切框、命名和格式转换这类胶水工作。
- **使用环境**：桌面浏览器优先；可能处理 4K～8K 图；在意文件隐私，不希望未发布的角色素材上传服务器。
- **成功感受**：不用先学一套美术软件，自动结果不完美时也能在同一页快速修完，并立刻拿到引擎能读的文件。

### 2.2 核心任务

1. 判断一张透明 sprite sheet 里有多少帧，并得到合理的初始帧框。
2. 用低摩擦交互修正错切、漏切、粘连和顺序问题。
3. 不查格式文档，直接下载 Phaser 3 或 Godot 4 所需产物。

## 3. 核心用户故事

### US-01：规整表快速进 Phaser

**As a** 正在用 Cursor 写 Phaser 3 Game Jam 项目的个人开发者，  
**I want** 把一张透明底、4×4 排列的角色动作表拖进网页后自动识别 16 帧，并导出 Phaser 图集，  
**So that** 我不用手量每个矩形坐标，也不用手写 atlas JSON，就能在十秒左右回到游戏代码里。

具体场景：用户从素材包拿到一张透明 PNG。检测正确时只需确认帧顺序，选择 Phaser JSON Hash 或 JSON Array，然后下载 ZIP。

### US-02：修正 AI 散排图并进 Godot

**As a** 用 ChatGPT/Midjourney 出图、再用外部工具去好背景的 Godot 4 开发者，  
**I want** 自动找出散排角色的各个帧，并能合并被拆开的帽子与身体、删除噪点框、补画漏掉的帧、调整顺序，  
**So that** 我可以得到干净的帧序列和 Godot 构建脚本，而不必逐帧裁图和导入。

具体场景：透明 WebP 中的角色大小和间距不完全一致。连通域检测给出初稿，用户在审校器里修正后下载 Godot ZIP。

### US-03：面对不确定结果仍可完成任务

**As a** 拿到一张间距混乱、部分帧粘连的透明角色表的 vibe coder，  
**I want** 在自动检测置信度不足时看到明确说明，并立即获得可调整的手动网格和手动画框工具，  
**So that** 工具不会悄悄导出错误素材，我也不必退出当前页面换另一个工具重做。

具体场景：自动检测无法可靠判断帧数。系统进入降级状态，预填一个估算网格；用户调整行列数、拆分粘连框或新增框后继续导出。

## 4. M1 功能清单

优先级含义：P0 缺失即不能发布；P1 是 M1 应有体验，但不单独阻断最小闭环；P2 可延后。为保证范围严格等于技术方案第 9 节，本版没有 P2 功能，所有后续能力直接列入“不做”。

| ID | 优先级 | 功能 | M1 交付边界 |
|---|---|---|---|
| F-01 | P0 | 纯前端应用骨架与基础中英双语 | 单页工具；处理与导出均在浏览器本地完成；可切换中文/英文；不含账号、云存储或服务端处理。 |
| F-02 | P0 | 透明底单图上传 | 支持拖放和文件选择；接收单张透明 PNG/WebP；校验格式、可解码性、透明通道与尺寸。 |
| F-03 | P0 | 策略 A：网格检测 | 对透明底规整网格和单行动画条生成候选帧框、帧数与置信状态。 |
| F-04 | P0 | 策略 B：连通域检测 | 对透明底散排素材生成候选帧框，并处理最小面积过滤、断件容差合并与近邻合并所对应的产品结果。 |
| F-05 | P0 | 策略选择与显式降级 | 自动采用更可信的 A/B 结果；低置信度或无有效结果时进入手动网格，并保留手动画框入口。 |
| F-06 | P0 | 审校视口 | 支持 fit、缩放、平移；显示帧框、选中态与尺寸；可浏览最高 8192×8192 的输入。 |
| F-07 | P0 | 帧框编辑与排序 | 新增、删除、移动、8 手柄缩放、合并、两点拉线拆分、多选和拖拽排序。 |
| F-08 | P0 | 撤销与重做 | 所有改变帧框几何、增删、合并、拆分和排序的操作均可回溯。 |
| F-09 | P0 | 图集打包基础能力 | 将审校后的帧打包成图集；默认帧间 padding 2px、extrude 1px；一键生成下载包。 |
| F-10 | P0 | Phaser 3 导出 | 导出 `atlas.png` 与 Phaser 官方 JSON Hash 或 JSON Array 描述文件。 |
| F-11 | P0 | Godot 4 导出 | 导出 `frames/` 帧序列与 `build_spriteframes.gd` 的 ZIP；不做实验性 `.tres` 直出。 |
| F-12 | P0 | 超大图与内存不足恢复 | 超过 8192 或预计/实际内存不足时明确阻止危险处理，提供降采样后重试或取消，不让页面无响应。 |
| F-13 | P0 | 黄金测试集 20 例与回归门禁 | 20 个 M1 适用样例均带期望帧数、bbox 容差和期望策略/降级行为；每次提交全量回归。 |
| F-14 | P1 | 检测参数调节 | 提供容差、最小面积、膨胀半径、合并距离；停止调节 300ms 后重算，并呈现真实处理状态。 |
| F-15 | P1 | 动画预览 | 时间轴实时播放、暂停、逐帧查看、FPS 调整和前后帧洋葱皮。 |
| F-16 | P1 | 编辑器快捷键 | 为选择、平移、缩放、增删、撤销/重做等提供与主流美术工具习惯相近的键盘入口，并有可查看的快捷键说明。 |
| F-17 | P1 | 图集高级设置 | 允许在自动尺寸与 POT 2048/4096/8192 之间选择，设置尺寸上限与是否允许 90° 旋转。 |
| — | P2 | 无 | 第 9 节未指定任何可延后但仍属于 M1 的独立能力；不以 P2 名义提前放入 M2/M3 功能。 |

## 5. P0 验收标准

以下场景中的“黄金样例”均指 `tests/golden/` 中带 ground truth 的 M1 样例。所有下载内容均需通过自动解包校验，不以“浏览器弹出下载”作为唯一成功条件。

### AC-F01 纯前端骨架与双语

**场景 A：素材不离开浏览器**  
Given 用户打开已部署的 SpriteFlow，并在测试中拦截全部网络请求  
When 用户上传一个有效样例，完成检测、编辑和任一导出  
Then 除加载静态站点资源外，不产生包含输入图片、像素数据、帧数据或导出文件的网络请求，全部处理可在静态资源加载完成后离线完成。

**场景 B：切换语言**  
Given 应用处于任一主流程状态  
When 用户把语言从中文切换为 English，或从 English 切换为中文  
Then 当前页面的按钮、状态、错误、空状态和对话框立即使用 `copy-m1.md` 对应语言，当前素材、帧框与编辑历史不丢失。

### AC-F02 透明底单图上传

**场景 A：拖放有效文件**  
Given 一张尺寸不超过 8192×8192、含至少一个非完全不透明像素且可解码的 PNG 或 WebP  
When 用户把文件拖入上传区  
Then 系统显示文件名和尺寸并进入检测流程，不要求选择图片类型。

**场景 B：点选有效文件**  
Given 与场景 A 相同的文件  
When 用户点击“选择图片”并选中该文件  
Then 结果与拖放入口一致。

**场景 C：拒绝非 M1 输入**  
Given 用户选择 JPG、GIF、APNG、视频、ZIP、多个文件或完全不透明的 PNG/WebP  
When 系统完成预检  
Then 不启动检测，显示与原因匹配的错误和可执行的返回动作；界面不提供 M1 未实现的去底、动图或批量处理入口。

**场景 D：解码失败**  
Given 扩展名为 PNG/WebP 但内容损坏或无法解码的文件  
When 系统尝试读取文件  
Then 显示“无法读取图片”错误，清理未完成任务，并允许重新选择文件。

### AC-F03 策略 A：网格检测

**场景 A：规整透明网格**  
Given 一个 ground truth 标记为规则网格的透明黄金样例  
When 自动检测完成  
Then 结果采用网格策略，帧数与 ground truth 精确一致，每个帧框与对应期望框的 IoU 均大于 0.9，并按从上到下、每行从左到右给出初始顺序。

**场景 B：单行动画条**  
Given 一个 ground truth 标记为单行动画条的透明黄金样例  
When 自动检测完成  
Then 结果采用网格策略，生成一行候选帧，帧数精确一致且每个 bbox IoU 大于 0.9。

### AC-F04 策略 B：连通域检测

**场景 A：透明散排素材**  
Given 一个 ground truth 标记为散排、至少包含两个有效帧的透明黄金样例  
When 自动检测完成  
Then 结果采用连通域策略，帧数与 ground truth 精确一致，每个帧框 bbox IoU 大于 0.9，低于样例最小面积标注的噪点不生成帧。

**场景 B：主体存在分离部件**  
Given 一个角色主体与帽子或武器分离、ground truth 将其标为同一帧的黄金样例  
When 使用该样例标注的 M1 默认检测设置运行  
Then 分离部件与主体只生成一个候选帧框，不被错误导出成多个动画帧。

### AC-F05 策略选择与显式降级

**场景 A：自动选择**  
Given 同时运行 A/B 后只有一个结果满足该黄金样例的期望策略与有效条件  
When 检测决策完成  
Then 审校器展示该策略的帧框，并在界面上标明采用的检测方式。

**场景 B：低置信度降级**  
Given 一个 ground truth 标记为必须降级的空图、严重粘连图或无法可靠分帧的样例  
When 自动检测结束  
Then 系统不把结果标记为“检测成功”，显示低置信度说明，进入手动网格模式，并预填系统估算的行列数。

**场景 C：人工完成降级流程**  
Given 用户处于低置信度降级状态  
When 用户调整行列数、应用网格，并用新增/拆分/删除帧框完成修正  
Then 可进入与自动检测成功相同的审校和导出流程，界面不要求重新上传文件。

### AC-F06 审校视口

**场景 A：浏览与定位**  
Given 一张有效图片已经生成至少一个帧框  
When 用户执行适合窗口、滚轮缩放和画布平移  
Then 图片与所有帧框保持坐标对齐，缩放中心和选中态可见，选中帧显示宽×高尺寸。

**场景 B：8K 输入**  
Given 一张可解码的 8192×8192 透明图片且测试环境内存满足处理要求  
When 图片进入审校器并执行平移、缩放和选中帧  
Then 视口可完成这些操作，界面不冻结到无法响应输入，帧框位置不因 fit/zoom 改变其原图坐标。

### AC-F07 帧框编辑与排序

**场景 A：几何编辑**  
Given 审校器中已有帧框  
When 用户分别移动帧框并拖动八个缩放手柄  
Then 帧框按指针变化更新，不能得到负宽或负高，尺寸标注同步更新。

**场景 B：增删、合并与拆分**  
Given 审校器中存在可操作帧框  
When 用户新增帧框、删除选中框、合并两个或多个选中框，或用两点拉线拆分一个框  
Then 帧列表与画布同步反映每次操作，且不保留已删除或被合并前的重复导出项。

**场景 C：排序**  
Given 时间轴中至少有三个帧  
When 用户把第三帧拖到第一位  
Then 时间轴、帧编号、预览播放顺序和最终导出描述文件均使用新顺序。

### AC-F08 撤销与重做

**场景：编辑历史可回溯**  
Given 用户依次执行移动、新增、合并、拆分、删除和排序操作  
When 用户连续撤销直到初始状态，再连续重做到最后状态  
Then 每一步都恢复对应的画布帧框和时间轴顺序；无可撤销/重做项时相应按钮禁用且不会改变数据。

### AC-F09 图集打包基础能力

**场景：默认设置打包**  
Given 审校结果至少含一个有效帧框，且所有帧框均在原图范围内  
When 用户以默认设置开始任一需要图集的导出  
Then 生成的图集中各帧不重叠，相邻帧内容之间至少有 2px padding，每帧边缘有 1px extrude，描述文件坐标与实际像素区域一致，并以单个 ZIP 提供下载。

### AC-F10 Phaser 3 导出

**场景 A：JSON Hash**  
Given 至少一个已审校帧并选择“Phaser 3 · JSON Hash”  
When 导出完成并解压 ZIP  
Then ZIP 含 `atlas.png` 和一个可解析 JSON；JSON 使用 Phaser 3 JSON Hash 结构，帧数量、名称、顺序与审校结果一致，每个 frame 坐标在 atlas 边界内。

**场景 B：JSON Array**  
Given 相同审校结果并选择“Phaser 3 · JSON Array”  
When 导出完成并解压 ZIP  
Then ZIP 含 `atlas.png` 和一个可解析 JSON；JSON 使用 Phaser 3 JSON Array 结构，并满足场景 A 的数量、名称、顺序与边界断言。

两种 Phaser 格式的 JSON 文件均命名为 `atlas.json`；未提供自定义命名能力的 M1 按审校顺序使用 `frame_000`、`frame_001`……作为帧名。

### AC-F11 Godot 4 导出

**场景：Godot 帧序列包**  
Given 至少一个已审校帧并选择“Godot 4”  
When 导出完成并解压 ZIP  
Then ZIP 包含 `frames/`、与审校帧数完全一致且按 `frame_000.png`、`frame_001.png`……命名的 PNG 帧，以及 `build_spriteframes.gd`；脚本引用的目录/文件名在 ZIP 中全部存在，不包含实验性 `.tres` 文件。

### AC-F12 超大图与内存不足恢复

**场景 A：尺寸超过上限**  
Given 用户选择任一边大于 8192 像素的可解码透明图片  
When 预检得到图片尺寸  
Then 系统不直接启动全分辨率检测，显示原尺寸、M1 上限和“降采样后继续/取消”；选择继续后最长边缩至不超过 8192 并重新预检，选择取消后回到上传空状态。

**场景 B：预计内存不足**  
Given 系统在处理前判断当前设备不足以安全处理原图  
When 预检结束  
Then 不进入可能导致页面崩溃的处理，显示内存说明与降采样选项；用户可降低目标尺寸后重试。

**场景 C：处理中内存失败**  
Given 检测或导出已经开始且发生可识别的内存分配失败  
When 失败被捕获  
Then 终止当前任务、恢复可交互界面、保留仍可用的原文件或审校数据，显示“降低尺寸后重试/返回编辑”动作，不自动刷新页面。

### AC-F13 黄金测试集与回归门禁

**场景 A：数据集完整**  
Given M1 黄金集目录  
When 测试工具枚举所有用例  
Then 恰有 20 个可运行样例，每例都包含期望帧数、期望 bbox 或容差、期望策略或降级行为，并覆盖规整透明网格、单行条带、透明散排、分离部件、噪点、粘连和必须降级的失败输入。

**场景 B：全量回归**  
Given 任意代码提交触发 CI  
When 黄金回归执行  
Then 20/20 用例通过：帧数精确匹配、每个需检测帧的 bbox IoU 大于 0.9、标注为降级的样例进入正确降级路径；任一断言失败时该回归 job 失败。

## 6. 页面与完整流程

M1 是单页工具，不把步骤拆成多个路由。页面随任务状态在上传、检测、审校和导出之间切换。

### 6.1 页面/区域清单

1. **上传空状态**：产品名、隐私说明、拖放区、选择图片按钮、支持格式与尺寸说明、语言切换。
2. **文件预检状态**：文件名、格式、尺寸；执行解码、透明通道、尺寸和内存风险检查。
3. **检测状态**：真实进度、当前阶段、取消动作；完成后进入审校，低置信度时进入降级提示。
4. **审校工作区**：主画布、帧框工具栏、检测参数侧栏、帧列表/时间轴、预览控制、撤销/重做、重新上传与导出入口。
5. **导出面板**：Phaser/Godot 格式、M1 图集设置、导出前摘要、处理中状态、下载结果。
6. **全局反馈层**：错误提示、确认对话框、短时成功提示、内存/超大图恢复面板与快捷键说明。

### 6.2 主流程

1. 用户进入上传空状态，看到“文件只在浏览器中处理”的明确说明。
2. 用户拖放或点选一张透明 PNG/WebP。
3. 系统预检；通过后开始 A/B 自动检测并显示真实进度。
4. 系统选择可信结果并进入审校工作区；用户检查帧数、边界和顺序。
5. 用户按需增删、移动、缩放、合并、拆分帧框，并调整顺序；需要时撤销/重做或调节检测参数重算。
6. 用户通过时间轴预览动作，确认结果。
7. 用户打开导出面板，选择 Phaser JSON Hash、Phaser JSON Array 或 Godot 4，并确认打包设置。
8. 系统本地打包，完成后下载 ZIP；用户可以返回编辑并再次导出。

### 6.3 异常分支

#### A. 检测低置信度或失败

1. 系统明确显示“没把握，已切到手动模式”，不使用成功语气。
2. 画布显示预估手动网格；侧栏提供行、列调整与“应用网格”。
3. 用户可继续新增、删除、拆分、合并帧框。
4. 只要得到至少一个有效帧框，即可继续预览与导出；若仍为零帧，导出按钮禁用并解释原因。

#### B. 超大图

1. 任一边大于 8192 时，预检停止。
2. 页面显示原始尺寸、上限及处理风险。
3. 用户选择降采样到允许尺寸后继续，或取消回到上传；M1 不提供云端处理或桌面端绕过。

#### C. 内存不足

1. 处理前预计不足时不启动；处理中失败时安全终止当前任务。
2. 页面保持可交互，说明是设备内存限制而非图片内容错误。
3. 上传/检测阶段提供降低尺寸后重试；导出阶段优先保留审校结果并允许返回编辑或降低尺寸后重试。

#### D. 不支持、非透明或损坏文件

1. 在预检阶段停止，不进入检测。
2. 分别显示格式不支持、M1 仅支持透明底、一次只能处理一张、或解码失败。
3. 用户可重新选择；不出现“去背景”“抽帧”“批量”等越界入口。

#### E. 导出失败或下载被浏览器阻止

1. 保留全部审校结果与导出选项。
2. 显示可重试动作；下载被阻止时提示用户允许下载后重试。
3. 不要求重新上传或重新检测。

## 7. 明确不做

以下均不属于 M1：

- 3D 素材管线。
- 视频输入、视频抽帧、视频抠像、智能抽帧、循环检测或视频 prompt 模板。
- 生成图片或视频；不取代 ChatGPT、Midjourney 等生成工具。
- 经典去底与 AI 抠图；M1 只接收已经透明的图片。
- 骨骼动画编辑器、部位拆分、遮挡补全、多角度/三视图编排。
- 账号体系、登录、云存储、服务端处理或用户素材上传。
- GIF/APNG 抽帧、ZIP 图片包、批量队列。
- libGDX、Cocos、Unity、通用 JSON、GIF 预览或其他引擎导出。
- pngquant/8-bit 量化压缩。
- 锚点对齐、尺寸归一、pHash/dHash 重复帧折叠、离群帧产品能力及其批量属性。
- Lemon Squeezy、License Key、付费门控或 Pro 权益。
- `.tres` 直出、Phaser 实机预览、导出即运行时代码、本地项目工作区。
- 音频、Tileset/Tiled 与位图字体管线。
- 桌面版。

## 8. M1 成功指标与退出标准

| 指标 | M1 目标 | 测量方式 |
|---|---|---|
| 首次结果速度 | 在参考桌面设备上，代表性 ≤4K 透明样例从确认上传到出现可导出的审校结果，P50 ≤10 秒；检测期间界面可响应。 | 对固定样例连续运行 10 次，记录开始检测至导出按钮可用的耗时与 UI 心跳。 |
| 首屏体积 | 首屏 JavaScript <300KB gzip。 | 对生产构建产物生成 gzip 体积报告；M2+ 大依赖不得进入 M1 首屏。 |
| 4K 连通域性能 | 4K 黄金样例的连通域检测 <500ms。 | Node/浏览器基准各记录处理耗时，以技术方案性能预算为准。 |
| 黄金集通过率 | 20/20，100% 通过。 | CI 全量回归：帧数精确、bbox IoU >0.9、降级路径正确。 |
| 端到端样例退出标准 | 1 张 Kenney 表 + 5 张透明 AI 图，6/6 可完成上传→检测/降级→审校→任一目标引擎导出。 | 按固定人工验收脚本执行，记录每例最终产物与必要人工步骤。 |
| 静默错误 | 标注为低置信度/失败的黄金样例中，0 例被当作成功结果直接放行。 | 检查降级标志、界面状态与导出前状态。 |
| 导出完整性 | 对可导出黄金样例，Phaser 两种格式与 Godot ZIP 的自动结构校验通过率 100%。 | 解压产物，解析 JSON、校验坐标/帧数/顺序和 Godot 文件引用。 |
| 隐私边界 | 处理 6 个端到端样例时，0 个素材或衍生数据网络上传请求。 | 浏览器网络拦截与离线复测。 |
| 超限可恢复性 | 超大图、预估内存不足、运行时内存失败 3 类用例均能回到可操作状态，页面崩溃率 0%。 | 人工/自动故障注入，验证降采样、取消和返回编辑路径。 |

M1 只有在全部 P0 验收标准通过、黄金集 20/20 通过，并满足“1 张 Kenney 表 + 5 张 AI 图跑通全流程”的退出标准后，才视为完成。
