# 多 Agent 开发流程方法论（Playbook）

> 提炼自 SpriteFlow 项目（2026-09-16 ~ 09-17）的实战运行：2 个 Gate、3 次契约变更、1 次授权例外、多轮打回循环全部走通。
> 用途：移植到其他项目。本文与具体模型名尽量解耦（模型每季度都在换，角色和机制是稳定资产），落地方案见第 3、4 节。

---

## 0. 核心思想（八条铁律）

1. **一切落盘为文件**——会话会丢、额度会用完、窗口会关，文件是唯一持久层。任何只存在于对话里的结论视为不存在。
2. **文件所有权 = 防冲突机制**——每个角色只能写自己的目录/文件，比分支策略更根本。并行事故的根源几乎全是越界写。
3. **生产与验收分离**——验收官只裁决、只出问题清单，绝不亲手改文件。自己改自己查等于没查。
4. **验收官与生产者必须异模型家族**——同一个模型盲点相同，同族审查是假审查。
5. **接口契约先行**——两个并行开发的角色之间必须先有冻结的契约（类型 + 协议 + 错误模型），否则产出必然无法拼装。契约是并行的前提，不是文档锦上添花。
6. **机械化验收优先于模型评审**——能写成测试/脚本/CI 门禁的标准，绝不靠模型"看"。测试是代码的法官，模型评审管文档与集成裁决。
7. **冲突不让机器拉扯，升级人类拍板**——同一阶段打回最多 2 轮，第 3 轮升级产品主人工裁决（僵局通常意味着需求歧义，需要人定义）。
8. **授权例外必须留痕**——当 A 角色必须改 B 角色的文件时（如实现者修测试基准），走"产品主授权 + 条件约束 + 单独提交 + 事后复核"的例外流程，绝不静默越界。

## 1. 角色体系（11 个）

### R0 产品主（人，不可替代）

- **职责**：每个 Gate 的最终拍板；范围裁决（契约变更、第 3 轮打回、"要不要塞进本版本"）；真实世界资源供给（生图、账号注册、支付、密钥）；按上线按钮。
- **为什么是人**：价值判断和责任承担无法委托。生图等需要真实身份/订阅的能力 agent 也拿不到。

### RC 协调者（常驻主会话，不是提示词角色）

- **职责**：流程指挥与状态跟踪；跨角色消息分发（把验收问题清单转给生产者、把契约修订转给受影响方）；**独立技术验证**（复跑测试、写一次性测量脚本、抽查提交范围）；存档提交（agent 们常忘记 commit，协调者兜底）；僵局仲裁支持；暂停/恢复快照。
- **模型与原因**：主力档即可（本项目用 GLM-5.3）。协调工作的难度在流程纪律、长上下文和状态记忆，不在单步推理深度；它是常驻会话，用旗舰纯属烧钱。
- **关键设计**：协调者**不生产任何角色交付物**（不写 PRD、不写代码），否则既当裁判又当运动员。它的产出只有：流程指令文本、验证报告、快照、手册维护。

### 生产角色（8 个）

| 角色 | 职责与交付物 | 为什么需要它（缺了会坏什么） |
|---|---|---|
| R1 产品经理 | PRD（用户故事、P0/P1/P2、Given/When/Then 验收标准、异常分支、明确不做清单）+ 双语文案表 | 范围纪律的源头。验收标准的质量决定下游所有角色的工作质量 |
| R3 架构师 | 仓库结构、技术选型+许可审计表、性能预算分解、**接口契约** | 并行开发的前提。契约错误 = 全线返工，单点成败角色 |
| R2 UI/UX 设计师 | 设计规范 + 单文件 HTML 静态稿（不是图片） | HTML 稿可直接照抄实现，杜绝"设计很美、实现抓瞎" |
| R4 核心工程师（算法/管线轨） | 纯逻辑模块（无 DOM 依赖、Node 可测）、单测、性能基准 | 算法与 UI 解耦 = 双轨并行的切面；纯模块可在 CI 独立验证 |
| R5 应用工程师（UI 壳轨） | 应用壳、交互、状态、接线 | 代码量最大但模式标准；只许调用管线包不许自研算法 |
| R6 QA 工程师 | 黄金测试集（带 ground truth）、回归 harness、E2E 计划 | **全程角色不是收尾角色**：黄金集先于代码存在，实现者对着它开发；ground truth 是产品的长期资产 |
| R7 DevOps / 唯一集成人 | CI 门禁、部署配置、根配置文件 | CI 是所有人的机械验收官；根文件单人集成防锁文件冲突 |
| R8 增长运营（上线后） | demo 脚本、社区发帖方案、落地页文案 | 独立于开发节奏，可在收尾期并行 |

### 审查角色（2 个）

| 角色 | 职责 | 模型要求 |
|---|---|---|
| R9 验收官 | 按 checklist 逐条裁决（证据 = 文件行号/实测），PASS/FAIL + 问题清单（P0/P1/P2），裁决书写入文件 | 与生产者**异族** + 高推理档 |
| R10 图像检验员 | 替无视觉能力的会话"看图并汇报"，量化测量 + 结构化报告 | **必须多模态**（轻量档即可，如 Flash） |

> R10 是实战中补位的角色：主会话和多数编码模型无视觉，素材验收、mockup 效果、导出产物检查都需要"眼睛"。它的报告也落盘（docs/inspections/）。

## 2. 流程骨架

```
Wave 1（并行）   PM ──────┐        架构师 ──────┐
                         ▼                          ▼
Gate 1          验收官：PRD 验收        验收官：架构+契约+许可审计
                         └──────────┬───────────────┘
                                    ▼  产品主拍板（契约冻结）
Wave 2（并行）   UI 设计师    核心工程师    QA（黄金集先行，可提前到 Wave 1.5）
                         ▼
Gate 2          验收官：UI 验收（核心工程继续，不受阻）
                         ▼
Wave 3（并行）   应用工程师    DevOps（根骨架其实要前置到 Wave 2 开工前）
                         ▼
Gate 3          验收官+QA：集成验收（E2E + 黄金回归 + 性能实测 + 许可终审）→ 产品主拍板 → 上线
Wave 4（上线后） 增长运营
```

**打回循环**（每个 Gate 内）：
```
生产者交付 → 验收官 FAIL（问题清单落盘）→ 清单转给生产者（附"只改你所有权内文件"）
→ 修复 → 同窗口复审（verdict-N 递增）→ PASS → 产品主拍板
→ 第 3 轮仍 FAIL：升级产品主人工裁决
```

**契约变更流程**（契约冻结后）：
```
任何角色发现缺口 → 停工，写变更申请文件（复现 + 条款位置 + 修订建议，不自行变通）
→ 架构师拟候选修订（升版本：加可选能力 minor / 改必填字段或语义 major）
→ 产品主批准 → 架构师落生效记录 + 提交 → 协调者分发同步给受影响角色 → 生产者恢复
```

**授权例外流程**（跨所有权修改时）：
```
申请者向产品主申请 → 授权文本带条件（最小 diff / 引用条款 / 全量排查同类 / 单独提交 / 事后由所有者复核）→ 执行 → 留痕
```

## 3. 模型分配：原则与原因

### 四条分配原则

1. **最强模型只给"单点成败"角色**——错误传播半径大的任务（契约设计、核心算法）失败代价是全局返工，省这里的钱最不划算。
2. **异族验收**——生产 GPT 系 → 验收 GLM；生产 GLM → 验收 GPT 高推理。同模型盲点相同。
3. **便宜模型给量大而模式化的角色**——CI 配置、看图汇报、脚本杂活。
4. **机械验收零模型**——测试、门禁、测量脚本是代码的法官，不需要也不应该由模型判断。

### 本项目的实际分配与原因（供复盘）

| 角色 | 模型 | 原因 |
|---|---|---|
| 协调者 | GLM-5.3 主力 | 流程纪律+长上下文，不需要单步深度 |
| PM | GPT-5.6 Sol（主力） | 产品判断+结构化写作，PRD 质量传导全局 |
| 架构师 | GPT-6 Astra（旗舰） | 契约是单点成败，值得最贵的脑子 |
| 核心工程师 | GPT-6 Astra（旗舰） | 全项目最难代码；有黄金集兜底仍保守用最强 |
| UI 设计师 | GLM-5.3 | HTML 稿模式化，双语文案稳 |
| 应用工程师 | GPT-5.6 Terra（均衡） | 代码量最大但模式标准，性价比 |
| QA | GPT-5.6 Sol | ground truth 标错一个，实现者追着幽灵跑 |
| DevOps | GLM-5.3 Flash（轻量） | 配置活，模式化 |
| 验收官 | 异族+高推理（GLM-5.3 或 Sol 高） | 对抗性审查 |
| 图像检验员 | GLM-5.3 Flash | 唯一硬要求是多模态 |

## 4. 角色与模型的关系：重新设计指南（回应"颠倒"之惑）

实战复盘下来，直觉上的"颠倒"确实存在：**旗舰模型当了最强壮的工人（架构师/管线），管理（协调者）和裁判（验收官）反而用主力档**。直觉上"最贵的脑子该当老板"，我们让"最贵的脑子当特种兵"。这不是失误，是两个设计取向的取舍：

**取向 A（本项目）：强模型做生产端单点**
- 逻辑：契约/算法的产出质量直接决定成败，且**没有机械化兜底**（写契约时还没有测试）；管理和验收有流程纪律（checklist、异族、落盘）兜底，对单步推理深度要求较低。
- 适用：项目早期（无测试资产）、任务规格化程度低时。

**取向 B：强模型做编排与裁决**
- 逻辑：当生产端**规格化程度高**（有冻结契约 + 黄金集测试兜底），生产的质量已由机械验收保证，旗舰下放是浪费；此时判断力最值钱的地方是"审"（验收、集成裁决）和"排"（任务分解、跨角色仲裁）。
- 适用：测试资产成熟后、或用便宜模型也能照规格干活的阶段。

**决策矩阵（重新设计时的工具）**——按两个轴给每个角色定档：

| | 错误传播半径大 | 错误传播半径小 |
|---|---|---|
| **规格化程度低**（无机械兜底） | 旗舰（契约、PRD、架构决策） | 主力（文案、运营） |
| **规格化程度高**（有测试/门禁兜底） | 主力~旗舰（核心算法——本项目保守用了旗舰，**其实有黄金集后可降**） | 均衡/轻量（CRUD 前端、CI、看图） |

验收端的档位 = 生产者档位镜像 + 推理档调高 + 强制异族。协调端 = 主力档 + 优先长上下文模型。

**三条松耦合建议**（让方法论活过模型迭代）：
1. 手册里角色只写**能力需求**（旗舰/主力/均衡/轻量/多模态），不写模型名；启动新项目时再映射到当期可用模型。
2. 模型池是双供应商（两家订阅互为备份）——本项目 R5 因单家额度耗尽停摆一周就是教训；关键角色应有"异供应商备选"而不只是"同家降档"。
3. 每个角色开工前用 10 分钟小任务校准当期模型的实际档位（模型季度间会漂移，命名不可靠）。

## 5. 实战教训（真实案例，全部发生过）

**机制有效性的证据**：
- 异族验收抓出真问题：Chrome Ctrl+D 快捷键冲突、PRD 与契约的三处不一致、可访问性语义缺失。
- 独立验收官抓出旗舰模型的错：架构师引用的库 API 与实际源码不符（验收官拉源码复验）、契约承诺了数据结构无法实现的语义（STALE_RESULT 缺源 bbox）。
- 实现者主动停工报告契约缺口（三次），而不是硬写——"发现缺口即停工"条款的价值。
- 许可门禁拦截演练真实生效（注入未审计依赖 → CI 红 → 合并被拦）。
- 机械化验收的价值：测量脚本替代肉眼判断素材是否合格（发现"合并了但没放大"的半成品手术）。

**流程事故与修复**：
- 发送顺序漏步：生产者修复时依赖词条还没录入，复审必然 FAIL 一次——修复依赖要环环确认发送，不要假设"改完 A 再验 B"能自动衔接。
- agent 通用毛病：干完活不 commit（发生过两次）→ 协调者兜底提交 + 在指令里明示"完成后自行提交"。
- 误操作透明化：DevOps 误 add 了别人的 WIP，立即软重置并自曝——鼓励这种透明文化，事故+披露比隐匿安全得多。
- 主会话编辑文件也会出错（一次 Edit 吃掉了下一个标题）——落盘后 grep 验证结构完整，协调者也要自检。

**资源现实**：
- 套餐额度会耗尽：R5 停摆一周。要设计"暂停-恢复"能力（快照文件 + WIP 保护令"勿动勿 reset"），而不是硬撑。
- 多模态是稀缺能力：多数编码模型看不了图，专设轻量多模态角色补位，报告落盘。
- 生图走旁路：coding 套餐不含生图，用开放平台 API 免费档（注意水印）+ 人工精修 + CC0 素材三路分工。

## 6. 移植清单（新项目 8 步启动）

1. 写技术方案文档（唯一事实来源，含里程碑与"不做清单"）
2. 写角色手册：提示词（通用背景块 + 职责 + 交付物 + 完成标准 + 禁止）+ **文件所有权表** + 验收 checklist
3. git init + README 门规（文档地图、所有权、提交纪律、密钥禁令）
4. 密钥/工具就位（env 变量 + .env gitignored + 实测一次）
5. 按当期模型池映射能力档位 → 开 Wave 1（PM ∥ 架构师）
6. 每个 Gate：验收官（异族）→ 打回循环 ≤2 轮 → 产品主拍板
7. 集成验收：E2E + 回归 + 性能 + 许可终审 → 上线动作清单（账号/支付/域名，全是产品主的）
8. 复盘：把本项目的教训表抄过来续写

**可复用的资产**（都在本项目仓库里有实战过的版本，可直接改用）：
- 文件所有权表格式（docs/agent-roles.md §0）
- 验收裁决格式（PASS/FAIL + P0/P1/P2 问题清单 + 证据行号 + 落盘路径）
- 打回循环标准话术（复审指令 / 修复指令 / 第 3 轮升级）
- 契约变更申请模板（复现 + 条款位置 + 修订建议 + 不自行变通声明）
- 授权例外四条件（最小 diff / 引用条款 / 全量排查 / 单独提交+复核钩子）
- 暂停快照模板（docs/PAUSE-*.md）
