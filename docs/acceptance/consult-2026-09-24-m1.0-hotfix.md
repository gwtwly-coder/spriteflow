## Q1 裁决：M1.0 走方案 a（零契约变更），但数据路径用 preview 命令裁剪，不用主线程全图 ImageBitmap

**结论**：方案 a，附一处关键修正——「源图 ImageBitmap 自行合成」若按 `createImageBitmap(file)` 全分辨率解码实现，违反架构主线程内存纪律（architecture-m1.md §4：主线程只持有原 File、≤1024 预览与有限 tile 缓存；8K 全图位图 ≈268MB）。正确路径是契约已有的 preview 通道：

- **数据路径**：`preview` 命令（契约 :755 PreviewRequest、:866 语义——任意图内矩形、`maxDimension` 整数 1…1024、返回独立像素、主线程 LRU 缓存，本就是为视口细节显示设计的）。每芯片请求 `sourceRect = frame.bbox` 的裁剪，`maxDimension=112`（56 CSS px × DPR2），客户端按 `Frame.canvas` 几何（统一画布 + `canvas.offset`）合成到 56×56 棋盘格芯片。`bbox=null` 空帧不请求，纯棋盘格占位。首屏可先用 `load.preview`（≤1024 全图）垫底低清版，可见芯片再升级（两级为可选优化，时间紧可先只做升级档）。
- **方案 b 否决**：契约 3.0.0 已生效，新增字段即 minor（3.1.0），M1.0 热修窗口不动契约；且 normalize 响应塞数百张 base64 缩略图破坏「结果小对象 + structured clone」不变量、放大每次重算开销，方向本身劣于复用 preview 通道。若未来实测 preview 通道不满足再议，版本路径为 3.1.0。

**性能护栏（须写入 ui-spec 修订，作为 R5 实现约束）**：

1. 懒渲染：仅渲染进入/接近视口的芯片（IntersectionObserver 或虚拟化），预取窗口 ≈ ±可见数；500 帧（desktop 上限）不一次性请求。
2. 缓存：芯片档（112²×4≈48KB/张）与播放档（Q2，320²×4≈400KB/张）分列 LRU，合计 ≤ 主线程缓存预算 32MiB（architecture §5.2）——芯片档上限 512 张 ≈24MB。
3. 调度：缩略图请求走后台空闲队列串行提交（Worker 单任务），用户发起的 detect/normalize/preview 优先；用户任务到来时挂起队列，响应回来时 editRevision/normalizationId 不匹配即丢弃。
4. 失效：normalize 成功（normalizationId 变化）清空缓存重填；排序/移动不重取像素（缓存键 = frameId + 几何）。
5. 建议实现形态：R5 抽一个共享的「帧裁剪位图服务」模块，芯片与 Q2 播放视口共用（后续侧栏组 3 也可复用），避免两套管线。

## Q2 裁决：播放渲染面落在时间轴头部左侧的固定预览视口；零契约影响（确认），需 ui-spec 修订（要点见下）

**落点选择**：时间轴左侧固定预览视口（§5.3.4 头部「动画预览」分组扩展为 [视口 + 控件]）。理由：

1. F-15 的交互簇（播放/暂停/步进/FPS/洋葱皮/擦洗芯片）全部在时间轴头部（ui-spec :299），渲染面与控件同址，形成「擦洗↔播放↔步进」最短操作回路。
2. 侧栏组 3「导出预览」（:348）职责是**选中帧**的规范化摆放检查（248×186、随草稿后台重算），把播放塞进去会混淆「检查摆放」与「检查动作」，且侧栏不适合常驻播放。
3. 主画布叠加层遮挡工作区、与 pan/zoom 状态耦合，对编辑流冲突最大。

**视口规格原则（具体尺寸 R2 定）**：固定方形视口（建议 96–128 CSS px、DPR 感知、棋盘格底）；内容 = 当前帧逻辑画布（uniform 模式取统一画布尺寸，per-frame 取最大帧画布 letterbox；bbox 内容按 `canvas.offset` 摆放；空帧 = 纯棋盘格占位一拍）。时间轴总高如需从 152px 调整，属布局变更，由 R2 权衡定值。**播放期间零 RPC 依赖**：帧位图经 preview 裁剪预取（当前 ±8），未就绪帧保持上一帧画面，绝不阻塞等待 Worker。

**零契约影响确认**：preview 命令（:755/:866）+ Frame 几何（:146）+ 现有 copy 词条（`preview.play/pause/previous/next/fps/onion_skin/onion_on/onion_off/empty`，copy-m1 :197-206；`shortcuts.play_pause` :302）全部现成；不新增契约字段、枚举或错误码。唯一文档影响 = ui-spec 修订。

**ui-spec 修订要点清单（R2 承接，随修订单分发）**：

1. §5.3.4 新增「动画预览视口」小节：位置（头部左侧固定 dock）、尺寸原则（方形、DPR、棋盘格底、时间轴新总高）、内容规则（逻辑画布/letterbox/空帧占位）。
2. 播放行为规范：按 FPS 计时逐帧推进（1–120 步进边界）、播放指针与芯片选中态/擦洗双向同步、播放中发生编辑（几何/排序/删除）的行为定义（建议：立即暂停并按新时间轴继续，R2 定稿）。
3. 洋葱皮规范：开关、前/后各 1 帧、透明度（建议前 0.30/后 0.20，纯 α 不染色，R2 可调）与步进共存。
4. 缩略图数据路径与懒渲染约束：Q1 的五条护栏原文落入（两级 LRU、可见性驱动、空闲队列让位用户任务、normalize 失效重建、500 帧行为）。
5. 状态清单（C 表）补条目：视口首帧加载中、播放态图标/aria 切换、空帧播放占位；词条优先复用 `preview.*`，确需新增（如视口加载态）走 PM 补 copy。
6. 写明侧栏组 3 与本视口的分工（动态动作预览 vs 选中帧摆放检查），防止再次混淆。
7. 修订记录注明来源（集成后产品主实测缺陷 1/2），走 ui-spec 版本修订流程。

## Q3 裁决：内容感知建议网格并入 M2；M1.0 做零契约的降级调参引导

**a) 版本路径澄清 + 并入 M2**。先纠正前提：契约当前为 **3.0.0**（不是 2.x），且 §4.2 建议网格公式（:319-321，含 EMPTY_INPUT 特例）是冻结的**默认输出语义**——按 §11（:1011）「改变必填字段、默认输出、像素语义或错误语义须 major」，替换该公式是 **4.0.0 major**，不是 minor；「2.1.0 minor」的提法不成立。加法式 minor（如 `Degradation` 增可选 `contentAwareGrid` 字段、旧公式不动）虽可行，但为边际收益新增 API 面、golden 用例与双字段维护，不值。裁决：**M1.1 不做，并入 M2 检测优化专题**（自适应膨胀上限、桥接敏感的合并距离、基于质心/中位尺寸的建议网格），届时由架构师按 §11 在 3.1.0（加法式）或 4.0.0（改默认）间裁决。

**立即可做的零契约动作（强烈建议随本次热修分发）**：把产品主这张 1536×1024 type-E 图交 R6 入黄金集（「只增不删」），当前断言 = 诚实降级路径（对应 reason + 建议网格精确值 + 手画 10 帧仅作人工参考不入断言）——把痛点固化为回归锚点，M2 改进时按基线差异流程更新。

**b) M1.0 缓解：做，零契约**。降级横幅/手动网格面板加「调参重试」引导：

- 利用现有 `DetectDiagnostics`（componentCount/filteredComponentCount/effectiveMergeDistancePx/effectiveDilationRadiusPx）生成针对性提示，例：「CCL 粘成 2 大块（当前合并距离 46px）→ 减小合并距离或膨胀半径；发丝/水珠等半透明桥接 → 提高 alpha 阈值后重试」。
- 一键「用当前参数重试检测」（现有 detect 流）+ 可选预设 chip（如「细碎部件」= 小合并距离 + 小膨胀 + 较高 alpha 阈值）。
- `DETECTION_DEGRADED` 语义、错误码、契约字段全部不动；新增几条 copy 词条（建议 `degraded.tune.*` 组）走 PM。

## Q4 裁决：视觉验证规程补充（在「PASS 必附运行截图」之上）

1. **证据分级**：验收书每条 UI 相关项标注证据类型（运行截图 / 录屏 / 自动化输出 / 实测记录），仅 DOM/文字断言不予 PASS——建议直接落成裁决书模板字段。
2. **状态截图矩阵**：按 ui-spec 状态清单（C 表）逐状态索证；暗色/亮色 × 中英至少覆盖关键状态；证据文件入 `docs/acceptance/evidence/<gate>-r<N>/`，裁决书行内引用文件名（可追溯、防张冠李戴）。本次缺陷 1 若早有「时间轴正常态」截图要求，UI 验收轮即会暴露。
3. **时序行为必须录屏**：播放/擦洗/拖拽/撤销重做/进度/取消/降级横幅出现等，截图不可证伪。
4. **像素级自动化断言**：E2E 对 `.thumb`、预览视口等 canvas 类元素加「非全透明」断言（如 ≥N% 像素 alpha>0——与产品主实测 atlas 35.6% 可见同思路）；关键屏 Playwright 截图基线入 CI，基线更新走评审，不静默。
5. **举证责任前移**：R5 自测标准同步升级为「截图/录屏随交付」，验收官只复核——生产者先证，验收官后查。
6. **抽样复现权**：验收官保留对任意状态当场要求复现（现场录屏）的权利，防静态截图摆拍。
