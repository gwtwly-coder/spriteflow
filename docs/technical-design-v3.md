# SpriteFlow v3 / v3.5 技术方案：角色拆部位 · 遮挡补全 · 极简绑骨

> 定位：v3 把 SpriteFlow 从「切帧工具」升级为「角色管线」——**一张人物图进来，一个会在游戏里走路的角色出去**。
> 上游文档：`docs/technical-design.md`（M1 方案与路线图）、`docs/interface-contract.md`（3.0.0/r4 现行基线）、`docs/m1-retrospective.md`（教训）。
> 本文是 v3 的奠基文档；PRD 与接口契约由 Wave 1 角色按流程产出。

---

## 0. 产品原则（三个不可妥协）

1. **像素级一致不变量**：拆出的每个部位 = 原图像素 + alpha 蒙版。**永不重采样 RGB**——头发就是原图那些头发像素，一个字节不变。这是对"切出的素材必须和原图大小颜色完全一致"的工程化承诺，也是对 M1 导出管线的直接复用。
2. **上手难度低于 Live2D**：Live2D 要求用户建模、画网格、绑参数。v3.5 的承诺是**零手工绑骨**——部件自动挂到人形骨架模板，动作来自预设库 + 参数滑杆（"拖一下摆姿势"），不做关键帧编辑器、不做权重刷。专业动画需求让用户去 Spine/Live2D，我们不抢。
3. **零服务器成本不破戒**：本地模型（SAM 系）按需懒加载走浏览器；生成类能力（LLM 语义定位、SD 补全）一律 BYOK 用户自带 key。与 M1 相同，部署是纯静态站。

## 1. 范围：做什么、不做什么

**做（v3 系列）：**
- 单张透明人物图 → 语义拆部位（头发/脸/眼/眉/嘴/躯干/上臂/前臂/手/大腿/小腿/脚等标准件）→ 每部件独立透明图
- 遮挡补全：被身体挡住的头发/肢体等，按上下文补全，双版本保留（整体补齐 / 局部合成，借鉴 Image To Slice 的用户自选模式）
- 极简绑骨：部件自动挂骨架（人形模板）→ 预设动作库（idle/walk/跑/挥手等）+ 姿势参数滑杆 → 导出
- 导出：**逐帧渲染序列/图集（默认，任何引擎可吃，复用 M1 导出管线）** + Godot Skeleton2D 场景 / Spine JSON / DragonBones JSON（Pro 进阶选项）

**不做（明确排除）：**
- 不做 Spine/Live2D 级专业编辑器（网格变形、蒙皮权重、物理、IK 调参——那是团队级数年工程）
- 不做生成（立绘本身交给 ChatGPT/MJ；我们管"生成之后"）
- 不承诺非人形角色自动绑骨（怪物/机械走纯点击拆件模式，绑骨提供通用两足模板但质量分层）
- 不碰 3D

## 2. 技术架构：三层管线

```
输入：单张透明人物图（可来自 M1 输出）
   ▼
【L1 语义定位】多模态 LLM（BYOK：GLM-4V/CogVLM/GPT 系，可配置）
   prompt 工程（参考 Image To Slice 开源实现：严格 JSON 输出、
   部位词表、bbox 用原图坐标、含 JSON 修复重试）
   → 输出：部位列表 {name, kind, bbox, confidence, occluded:true/false}
   ▼
【L2 蒙版精修】SAM 系本地模型（onnxruntime-web，WebGPU 优先/WASM 回退）
   bbox 作为 box prompt → 像素级蒙版；用户可点击增删部位（SAM 交互点）
   → 部位 = 原图像素 × 蒙版（不变量在此保证）
   ▼
【L3 遮挡补全】双档：
   本地档：LaMa ONNX（结构性延续：发梢/衣摆/四肢边缘）
   高质量档：BYOK SD-inpainting（复杂遮挡）
   → 双版本保留，用户自选
   ▼
【v3.5 极简绑骨】
   部位 → 人形骨架模板自动挂接（按部位 bbox 质心匹配骨骼槽位）
   → 预设动作库（参数化：walk 幅度/速度，idle 呼吸深度…）
   → 导出：逐帧渲染序列（默认）/ Godot Skeleton2D / Spine JSON
```

### 2.1 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 语义定位用什么 | 多模态 LLM API（BYOK），不用本地分类模型 | Image To Slice 已验证该范式工程可行；LLM 天生会给部位**命名和分类**（"left_arm"），本地模型做不到；bbox 精度不足由 L2 SAM 精修兜底 |
| 精确蒙版用什么 | mobile-SAM 级本地模型 + box/point prompt | 精度、零边际成本、隐私；模型 ~40MB 从 R2 懒加载 + CacheAPI 长缓存 |
| 人形判定失败怎么办 | 降级为纯点击拆件模式（SAM 交互点，无语义命名） | 非人形（怪物/机械）不硬撑自动管线；与 M1"诚实降级"原则一致 |
| 补全双版本 | 保留"整体补齐"+"局部合成"两版供用户自选 | Image To Slice 验证的用户自选模式，不自动判定 |
| 绑骨骨骼来源 | 内置人形模板骨架（约 15 骨），按部件语义自动挂接；部件缺失时相邻骨骼合并挂接 | 部件级权重天然干净（一部件一骨），无需蒙皮权重 |
| 动作来源 | 参数化预设动作库（每种动作 = 参数化骨骼姿态曲线），用户调滑杆不改关键帧 | "比 Live2D 上手低"的落点；预设库是持续运营资产（护城河） |
| 导出主形态 | **逐帧渲染**（把骨骼动画渲染成帧序列/图集） | 任何引擎可吃、完全复用 M1 导出管线与质量验证；骨骼格式导出（Godot/Spine）作为 Pro 选项，且规避 Spine 格式版本漂移风险 |
| 包结构 | 新增 `packages/rig`（纯 TS：骨架模板/姿态曲线/逐帧渲染器，Node 可测）+ `packages/segment`（SAM 会话/蒙版工具）；UI 在 apps/web 加工作区模式 | 延续"纯逻辑包与 UI 分离"的 M1 架构红利，黄金回归可直接跑 |

### 2.2 与 M1 资产的复用关系

- **编辑器骨架**：拆部位审校直接复用 M1 的 Canvas 视口/选中/缩放/撤销——新增"部件层"（蒙版高亮、点击增删）
- **导出管线**：逐帧渲染产物 = M1 的帧序列/图集输入，Phaser/Godot 导出零改动
- **黄金集体系**：新增人物病例集（真实 AI 立绘 × 部位 truth 标注）；像素一致不变量用程序断言（部位像素 ⊆ 原图）
- **任务分配规则 v2**：直接适用

## 3. 里程碑

| 阶段 | 内容 | 退出标准 |
|---|---|---|
| **v3.0-alpha**（拆部位核心） | L1 语义定位（BYOK）+ L2 SAM 精修 + 部位导出 + 点击增删交互 | 人形立绘 30 秒内完成拆件；部位像素 100% 来自原图（程序断言）；黄金人物集 ≥10 例通过 |
| **v3.1**（遮挡补全） | LaMa 本地档 + BYOK SD 档 + 双版本 UI | 结构性遮挡（发梢/衣摆）视觉连续；双版本保留与切换 |
| **v3.5**（极简绑骨） | 自动挂骨架 + 预设动作库（首发 5 动作）+ 逐帧渲染导出 + Godot 骨骼导出 | **零手工绑骨**完成 idle+walk；Godot 真机播放验证；"30 秒一个会走的角色"全流程实测 |

## 4. 风险清单

| 风险 | 应对 |
|---|---|
| SAM 对 Q版/厚涂风格蒙版质量不稳 | 黄金人物集先行验证；box+point 混合 prompt；蒙版手刷兜底工具 |
| LLM bbox 精度不足/部位漏检 | 定位只做"粗定位+命名"，精修交给 SAM；用户点击增删是一等交互；prompt 词表迭代（借鉴 Image To Slice 的修复重试） |
| 遮挡补全质量不达用户预期 | 话术分层（结构性延续 vs 复杂遮挡）；双版本自选；BYOK 档给质量上限 |
| 浏览器算力（SAM/LaMa/逐帧渲染） | WebGPU 优先 WASM 回退；模型懒加载；性能预算进契约；移动端限制图尺寸 |
| Spine/DragonBones 格式漂移 | 逐帧渲染是默认主形态（引擎无关）；骨骼导出为 Pro 选项并锁定版本 |
| BYOK 摩擦（用户无 key） | 免费层完整可用本地档（SAM+LaMa）；BYOK 只影响语义定位与高质量补全 |
| 骨架模板对非标体型失败 | 部位缺失时合并挂接 + 手动微调（拖部件到骨骼）；非人形走点击模式 |

## 5. 验收策略（继承 M1 教训）

- **视觉证据强制**：拆件/补全/动画的每项验收附截图录屏（playbook §6.3）
- **端到端断言**：部位导出必须断言像素来源（⊆原图）、绑骨导出必须 Godot 真机播放
- **可用性基准**："30 秒一个会走的角色"作为 v3.5 的 P0 验收指标，产品主亲手实测
- **黄金人物集**：10+ 例真实 AI 立绘（Q版/厚涂/像素风/非标体型），产品主供图
