> 文档版本：v3.0-alpha v1.0（Wave 1 初稿）
> 产品角色：产品经理
> 事实来源：`docs/technical-design-v3.md`，其中第 1 节（做什么/不做什么）与第 3 节里程碑 v3.0-alpha 行为范围裁决依据
> UI 文案来源：`docs/copy-v3.md`（词条编号延续 `docs/copy-m1.md` 第 1–16 节）
> 上游背景：M1 已完工（`docs/prd-m1.md`、`docs/interface-contract.md` 3.0.0/r4、`docs/m1-retrospective.md`）

## 1. 产品定义

v3.0-alpha 在已上线的 M1 切帧工具旁边新增「拆部位」工作区：接收一张透明底人物立绘，先由用户自带 key 的多模态 LLM 完成语义定位（部位命名与粗框），再由本地 SAM 模型把粗框精修为像素级蒙版，用户用点击增删修正，最终把每个部位导出为独立透明 PNG。

v3.0-alpha 要验证的不是"任何图都能全自动拆对"，而是这条最短闭环是否成立：

**透明人形立绘 → L1 语义定位（BYOK）→ L2 SAM 蒙版精修 → 点击增删审校 → 部位 PNG 包。**

产品承诺是"人形立绘 30 秒完成拆件"与"部位像素 100% 来自原图"，不是"全自动万能"。当语义定位没有把握（非人形图）、用户未配置 key、LLM 调用失败或本地模型加载失败时，产品必须显式降级到本地点击模式并如实告知，不能静默输出看似成功的错误结果——这是对 M1"诚实降级"原则的直接延续。

### 1.1 范围裁决

- v3.0-alpha 功能范围严格等于技术方案第 3 节 v3.0-alpha 行：L1 语义定位（BYOK）+ L2 SAM 精修 + 部位导出 + 点击增删交互；加上验证这些能力所必需的黄金人物集（同一行退出标准明确要求"黄金人物集 ≥10 例通过"）。
- L3 遮挡补全（LaMa 本地档、BYOK SD 档、"整体补齐/局部合成"双版本 UI）整体属 v3.1。v3.0-alpha 对 L1 返回的 occluded 标记最多如实展示（P1），不做任何补全动作。
- 绑骨、骨架模板、预设动作库、姿势滑杆、逐帧渲染与 Godot Skeleton2D / Spine JSON / DragonBones JSON 导出全部属 v3.5；本版界面不出现任何相关入口。
- 蒙版手刷工具不进 v3.0-alpha：点击增删是本版唯一的蒙版修正交互；手刷是否进 v3.1，视黄金人物集对 SAM 蒙版质量的验证结果再定（技术方案第 4 节风险应对）。
- 输入沿用 M1 透明底边界：单张、可解码、完全不透明像素占比不高于 99% 的 PNG/WebP，任一边不大于 8192；不做去底，非透明图直接拒绝（沿用 M1 文案）。超大图降采样与内存不足恢复沿用 M1 行为。
- 与 M1 隐私承诺的差异必须显式：L1 会把图片发送到用户配置的 LLM 服务商（BYOK 直连）。未配置 key 时不产生任何携带图片数据的网络请求，全部能力本地完成。SAM 模型文件按需从静态资源加载并本地缓存，不属于素材上传。
- 像素级一致不变量中的"原图"指当前工作图（与 M1 契约第 2 节工作图像素语义一致）：用户授权降采样后，部位像素来自降采样后的工作图；不变量约束的是部位提取过程本身——从工作图到部位，永不重采样 RGB。
- 部位之间不承诺互斥，也不承诺覆盖工作图全部前景像素：一个像素可以属于多个部位，也可以不属于任何部位（如身体缝隙）。边界由用户点击增删控制——这正是点击增删被列为一等交互的原因。
- 部位导出唯一形态为"独立透明 PNG ZIP 包"（部位图 + 清单 + 说明）。不对部位包做图集打包；Phaser/Godot 等引擎格式导出仍只在 M1 切帧工作区提供。
- 部位审校不设 M1 式"确认审校"强制门槛：保留至少一个部位即可导出，以支撑 30 秒指标。部位重命名、置信度与遮挡标记展示、快捷键为 P1。
- 桌面浏览器为验收对象；移动端沿用 M1 限制策略，不是 v3.0-alpha 验收对象。

## 2. 目标用户

### 2.1 核心画像

**画像一（延续 M1 PRD 2.1 的 vibe coder）**：用 Cursor、Claude 等写 Phaser/Godot 游戏、用 ChatGPT/Midjourney 出图的国内外独立开发者、Game Jam 参与者。v3 为同一人群增加新任务：把整张立绘拆成部件，用于换色换装、差分表情、程序化拼装，以及为动画准备分层素材。他们同样不熟悉 Photoshop 的图层与蒙版工作流，最讨厌用套索一块块抠图、裁图、再逐个命名导出。

**画像二（新增：想把立绘变成会动的角色的游戏开发者）**：

- **身份**：独立开发者、Game Jam 参与者、小团队里的全栈；已经用 AI 生成满意的角色立绘，下一步想让角色在游戏里动起来（idle、走路、挥手）或做换装/差分。
- **技能结构**：会引擎与脚本，看得懂文件结构；不会 PS 分层抠图，被 Live2D/Spine 的"建模—网格—权重"学习曲线劝退，也请不起美术。
- **典型输入**：单张透明底人形立绘（AI 生成后已去底），全身单角色。
- **当前做法**：在 PS 里用套索/魔棒逐块抠出部件再逐个导出（一两个小时且边缘脏）；或放弃动画只用静态立绘；或硬学 Live2D 半途而废。
- **核心痛点**：生成工具给整图、动画工具要分层，中间的"拆件"是断层；拆出来的文件还得命名成 body part 才能被引擎和动画工具识别。
- **使用环境**：桌面浏览器；素材隐私敏感（未发布角色）；能接受自带 LLM key 换取自动命名，也希望没有 key 时照样能干活。
- **成功感受**：一张图拖进去，30 秒拿到一包文件名就是部位名的透明 PNG；结果不完美时点几下就能修完。
- **与 v3 路线的关系**：v3.0-alpha 给他的部位包既能立刻用于换装/差分/手工分层动画，也是 v3.5"零手工绑骨"的直接输入。

### 2.2 核心任务

1. 从一张人形立绘得到带语义命名的部位初稿与像素级蒙版。
2. 用低摩擦的点击增删修正多切、漏切与蒙版毛边；没有 key 或图不是人形时仍能完成任务。
3. 下载结构确定的部位 PNG 包，直接进引擎或后续工具，不再手工裁图与命名。

## 3. 核心用户故事

### US-01：人形立绘 30 秒拆成换装素材

**As a** 正在给 Phaser 游戏做角色换装系统的独立开发者，
**I want** 把一张透明底人形立绘拖进拆部位工作区，自动得到头发/脸/躯干/左臂等按标准命名的独立透明 PNG，
**So that** 不用打开 Photoshop 逐块抠图，30 秒左右就能开始写换色、换件的代码。

具体场景：用户此前配置过一次服务商 key。上传后 L1 返回部位表、L2 生成蒙版；左臂蒙版多带了一小块背景，切到"减区域"点两下，导出 ZIP，`parts/` 里每个文件名就是部位名。

### US-02：为"会动的角色"准备分层素材

**As a** 想让立绘在游戏里走起来的 Godot 开发者，
**I want** 把角色按标准部位拆干净，每个部位一张独立 PNG，并在清单里带上部位名与原图位置，
**So that** 现在可以先做分层动画或交给其他动画工具，之后绑骨能力上线时这张图能直接用。

具体场景：用户接到 walk 动画需求，需要头/躯干/四肢分层图。拆件导出后按 `parts.json` 的名称与 bbox 在引擎里把部位拼回原样验证，一层不缺、颜色不差。

### US-03：没有 key、图也不是人形，照样拆完

**As a** 没有配置任何 LLM key、素材又是一只机械怪物的 Game Jam 选手，
**I want** 在语义定位不可用时被明确告知，并直接进入本地点击模式，点出需要的几个部件并导出，
**So that** 工具不因为"没 key"或"不是人"把我挡在门外，我也不必换一个工具重做。

具体场景：上传机械怪物，L1 判定非人形，界面如实说明并切入点击模式；用户点出 6 个部件，导出 `part_000` 起命名的 PNG 包，全程零网络请求携带图片。

## 4. v3.0-alpha 功能清单

优先级含义与 M1 相同：P0 缺失即不能发布；P1 是应有体验，但不单独阻断最小闭环；P2 可延后。为保证范围严格等于技术方案 v3.0-alpha 定义，本版没有 P2 功能，可延后能力一律列入"明确不做/后续版本"。

| ID | 优先级 | 功能 | v3.0-alpha 交付边界 |
|---|---|---|---|
| V-01 | P0 | 拆部位工作区与透明立绘输入 | 与 M1 切帧工具并存的独立工作区；复用 M1 上传、预检、超大图与内存恢复规则；接收单张透明 PNG/WebP 人形立绘；切换工作区时对未完成工作弹确认。 |
| V-02 | P0 | L1 语义定位（BYOK LLM） | 服务商与 key 的本地配置；调用前的图片外发告知；严格 JSON 部位表（名称/kind/bbox/置信度/遮挡标记）与解析失败修复重试；失败原因分类展示。 |
| V-03 | P0 | L2 SAM 蒙版精修（本地模型） | 模型按需懒加载并长缓存（约 40MB 级）；WebGPU 优先、WASM 回退并提示性能差异；把 L1 粗框精修为像素级蒙版；部位 = 原图像素 × 蒙版。 |

| V-05 | P0 | 部位导出（独立透明 PNG 包） | 每部位一张内容紧框、1:1 不缩放的透明 PNG + `parts.json` 清单 + `README.txt` 的 ZIP；导出前执行像素一致程序断言；下载包含结构校验。 |
| V-06 | P0 | 诚实降级与异常恢复 | 非人形 → 纯点击模式；未配置 key / LLM 调用失败 → 本地点击模式兜底与配置引导；模型加载失败 → 可重试恢复且不重传图片；超大图与内存沿用 M1。 |

| V-08 | P1 | 部位重命名与排序 | 部位卡重命名（同步导出文件名，校验命名合法并处理冲突）与列表排序；不阻断闭环。 |
| V-09 | P1 | 置信度与遮挡标记展示 | 部位卡展示 L1 置信度与"被遮挡"提示；仅提示不做处理，补全属 v3.1。 |

## 5. P0 验收标准

以下场景中的"黄金人物样例"指黄金人物集中带部位 truth 的人形样例。所有下载内容均需通过自动解包校验，不以"浏览器弹出下载"作为唯一成功条件。

### AC-V01 拆部位工作区与输入

**场景 A：进入工作区并上传**
Given 拆部位工作区已打开，用户持有一张任一边不大于 8192、可解码、完全不透明像素占比不高于 99% 的透明 PNG/WebP 人形立绘
When 用户把文件拖入上传区或点选该文件
Then 工作区显示文件名与尺寸并进入拆件流程；上传、预检与各类拒绝行为与 M1 相同错误场景一致（复用 copy-m1 对应词条）。

**场景 B：拒绝不适用输入**
Given 用户选择 JPG、GIF、APNG、视频、ZIP、多个文件，或完全不透明像素占比严格大于 99% 的图片
When 系统完成预检
Then 不启动拆件，显示与原因匹配的错误和可执行的返回动作；界面不出现去底、动图或批量入口。

**场景 C：工作区切换保护**
Given 拆部位工作区存在部位数据或进行中的任务
When 用户切换到 M1 切帧工作区（或反方向切换）
Then 系统显示确认对话框，说明当前部位与编辑记录将被清空；确认后进入目标工作区初始状态，取消则留在原地。

### AC-V02 L1 语义定位（BYOK）

**场景 A：配置成功后的自动定位**
Given 用户已保存可用的服务商与 key，并上传一个黄金人形样例
When L1 调用成功
Then 界面显示带语义名称的部位初稿并进入 L2 蒙版精修，各阶段显示真实进度；完成后显示"识别到 {count} 个部位"摘要。

**场景 B：图片外发知情**
Given 用户已配置 key 且即将发起 L1 调用
When 调用发起前与执行中
Then 界面明确显示"语义定位会把这张图片发送到你配置的 {provider}"；未配置 key 时，应用不产生任何携带图片数据的网络请求。

**场景 C：key 与调用失败**
Given key 无效、网络错误、超时或服务商返回错误
When 自动重试（含 JSON 修复重试）次数用尽
Then 显示与原因匹配的失败说明（key 无效/网络/额度/无法解析），提供"重试语义定位"与"使用点击模式"两个动作；不使用成功语气，不静默清空已得到的部位。

**场景 D：JSON 解析失败重试**
Given 服务商返回的内容不符合约定的 JSON 结构
When 修复重试执行
Then 重试期间显示真实处理状态；成功则按场景 A 继续；仍失败则按场景 C 处理。

**场景 E：key 本地存储**
Given 用户已保存 key
When 浏览器存储被清除或用户手动清除
Then key 被清除且 L1 回到未配置状态；key 仅出现在发往用户所选服务商的请求中，不出现在任何其他网络请求里。

### AC-V03 L2 SAM 蒙版精修

**场景 A：模型懒加载与缓存**
Given 用户首次使用拆部位能力
When 流程需要本地模型
Then 显示真实下载进度与体积（约 {size} MB），完成后写入本地缓存；再次使用时不重复下载，模型直接就绪。

**场景 B：WebGPU 不可用回退**
Given 当前浏览器不支持 WebGPU
When 模型初始化
Then 自动回退到兼容后端并提示性能差异，拆件流程可正常完成，不作为错误弹出。

**场景 C：蒙版生成与不变量**
Given L1 已返回部位粗框
When L2 完成
Then 每个部位获得像素级蒙版，画布以蒙版高亮显示部位；每个部位的像素满足"原图像素 × 蒙版"不变量（断言口径见 AC-V05 场景 B）。

**场景 D：模型加载失败与恢复**
Given 模型下载或初始化失败
When 失败被捕获
Then 界面保持可交互，显示失败原因与"重试加载"；重试不需要重新上传图片；该状态下自动拆件与点击模式均明确标注不可用的原因（二者依赖同一本地模型），不出现无解释的禁用按钮。

### AC-V04 部位审校与点击增删

**场景 A：点击加/减区域**
Given 审校器中存在至少一个部位且本地模型就绪
When 用户在"加区域"或"减区域"工具下点击画布
Then 点击位置作为提示更新选中部位的蒙版，画布高亮与部位尺寸即时更新；操作可撤销。

**场景 B：新增与删除部位**
Given 审校器处于可编辑状态
When 用户用"新增部位"点击图中区域，或删除选中部位
Then 新部位同时出现在列表与画布（无语义命名时默认名从 `part_000` 起）；被删除部位从列表、画布与导出数据中消失；两者均可撤销、重做。

**场景 C：撤销与重做**
Given 用户依次执行加区域、减区域、新增部位、删除部位操作
When 连续撤销直到初始状态，再连续重做到最后状态
Then 每一步都恢复对应的部位集合与蒙版；无可撤销/重做项时相应按钮禁用且不改变数据。

**场景 D：视口行为**
Given 一张已产生部位的有效图片
When 用户执行适合窗口、滚轮缩放和画布平移
Then 图片、蒙版高亮与部位边界保持坐标对齐；8K 输入可浏览；缩放与平移不改变部位的原图坐标（沿用 M1 审校视口行为）。

### AC-V05 部位导出

**场景 A：下载包结构（M1 式结构校验）**
Given 审校结果包含至少一个部位
When 用户执行导出并解压 ZIP
Then ZIP 包含 `parts/<部位名>.png`、`parts.json` 与 `README.txt`；PNG 数量与部位数完全一致；文件名唯一且合法（沿用 M1 帧名规则，禁止保留设备名）；`parts.json` 可解析，记录每个部位的名称、kind 与原图 bbox，并与 PNG 一一对应。

**场景 B：像素级一致不变量（程序断言口径）**
Given 任一导出部位 PNG 与当前工作图
When 断言程序运行
Then 同时满足三条：① 部位 PNG 中每个 alpha>0 像素的 R/G/B 三通道与工作图同坐标像素逐字节相等（部位像素 100% 来自原图，永不重采样 RGB）；② 蒙版内像素的 alpha 与工作图同坐标 alpha 相等（契约采用强于"只减不增"的规则：extractPartPixels 对蒙版内像素复制源 RGBA）；③ 蒙版外像素 alpha 为 0。三条断言在部位像素数据生成时与部位 PNG 编码后解码复验时各执行一次，任一不通过即中止导出并显示"像素校验未通过"，不生成下载文件；同一断言（含编码后复验）同时进入黄金回归。

**场景 C：紧框与不缩放**
Given 任意已确认部位
When 部位 PNG 生成
Then 每张部位 PNG 为该部位内容的紧框，比例 1:1、不缩放、不新增颜色；依据 `parts.json` 的 bbox 可把全部部位按原位拼回工作图。

**场景 D：零部位禁用**
Given 当前部位数为 0
When 用户查看导出入口
Then 导出按钮禁用并说明"至少保留一个部位才能导出"。

### AC-V06 诚实降级与异常恢复

**场景 A：非人形降级**
Given 一个黄金集标注为非人形的样例，或 L1 无法给出有效人形部位表的人形图
When L1 判定完成
Then 界面不使用成功语气，显示"这张图不像人形角色"类说明并进入纯点击模式（无语义命名，部位默认名从 `part_000` 起）；用户仍可通过点击完成拆件与导出，无需重新上传。

**场景 B：未配置 key**
Given 用户从未配置 LLM 服务商与 key
When 上传完成
Then 界面提供两条明确路径："配置语义定位自动拆部位"与"直接使用点击模式"；选择点击模式后流程与非人形降级一致；全程不产生携带图片数据的网络请求。

**场景 C：LLM 失败进入点击模式**
Given L1 调用失败（AC-V02 场景 C）
When 用户选择"使用点击模式"
Then 进入与非人形降级相同的交互；已上传的图片与已得到的部位（若有）保留，不要求重新上传。

**场景 D：模型加载失败恢复**
Given SAM 模型加载失败（AC-V03 场景 D）
When 用户执行重试
Then 无需重新上传即可继续；连续失败时说明可能原因（网络、浏览器存储）并保持页面可操作。

**场景 E：超大图与内存**
Given 任一边大于 8192 的可解码透明图片，或处理前预计内存不足
When 预检结束
Then 沿用 M1 行为：阻止危险处理，提供"降采样后继续/取消"或内存说明；用户授权降采样后，拆部位在缩小后的工作图上进行，部位像素来自该工作图。

### AC-V07 黄金人物集与回归门禁

**场景 A：数据集完整**
Given v3 黄金人物集目录
When 测试工具枚举所有用例
Then 至少 10 例真实 AI 人形立绘，覆盖 Q版、厚涂、像素风与非标体型，每例包含期望部位集合（名称/kind/bbox 容差）与期望路径（正常拆件或降级）；另含至少 1 例非人形降级锚点（不占 10 例配额）。

**场景 B：全量回归**
Given 任意代码提交触发 CI
When 黄金人物回归执行
Then 每个人形例通过：部位集合与期望在容差内匹配、全部导出部位通过像素一致断言；非人形锚点进入正确降级路径且无成功语气放行；任一断言失败时该回归 job 失败。

**场景 C：可重复执行**
Given CI 环境
When 回归运行
Then L1 依赖通过录制的响应样本回放，不真实调用外部 API、不使用用户 key；本地模型推理路径与线上用户路径一致，结果可重复。

## 6. 页面与完整流程

v3 工作区与 M1 切帧工作区并存于同一单页应用；各工作区内部仍不拆多路由，页面随任务状态切换。

### 6.1 页面/区域清单

1. **工作区切换入口**：切帧 / 拆部位两个模式的常驻入口与切换确认。
2. **拆部位上传空状态**：拖放区、选择图片按钮、隐私差异说明（本地处理 + 语义定位外发告知）、语言切换、BYOK 配置入口。
3. **BYOK 配置面板**：服务商选择、key 输入与保存/清除、key 存储与外发范围说明。
4. **拆件过程状态**：L1 调用、L2 精修、本地模型下载/加载的真实进度、后端回退提示与取消动作。
5. **部位审校工作区**：主画布（图片 + 部件层蒙版高亮）、点击增删工具栏、部位列表、撤销/重做、重新拆件、导出入口。
6. **部位导出面板**：导出摘要与格式说明、处理中状态（含像素校验阶段）、下载结果。
7. **全局反馈层**：降级横幅（非人形/无 key/LLM 失败）、错误提示、确认对话框（删除部位、重新拆件、切换工作区）、快捷键说明（P1）。

### 6.2 主流程

1. 用户进入拆部位工作区，看到隐私说明；可选先配置服务商 key。
2. 用户拖放或点选一张透明人形立绘，系统预检；通过后进入拆件。
3. 已配置 key：L1 语义定位 → L2 蒙版精修，显示真实进度；未配置 key：展示"配置 key / 直接点击模式"选择。
4. 用户在审校工作区检查部位初稿，用加/减区域、新增/删除部位修正结果；需要时撤销/重做或重新拆件。
5. 用户打开导出面板，系统执行像素一致校验后生成本地 ZIP 并下载；用户可返回继续修改并再次导出。

### 6.3 异常分支

#### A. 非人形或 LLM 失败降级

1. 系统明确说明"没硬猜"，不使用成功语气。
2. 进入纯点击模式：新增部位 + 加/减区域完成全部拆件工作。
3. 不要求重新上传；已得到的部位保留，用户可继续增删。
4. 保留至少一个部位即可导出；零部位时导出禁用并解释原因。

#### B. 本地模型加载失败

1. 错误明确指向模型加载，说明自动拆件与点击模式均依赖它。
2. 提供"重试加载"，重试不重传图片；连续失败时给出可能原因与建议。
3. 页面保持可交互，已上传图片与部位数据不丢失。

#### C. 超大图与内存不足

沿用 M1：预检阻止 + 降采样后继续/取消；运行时内存失败安全终止并保留数据。降采样授权后拆部位在工作图上进行。

#### D. 不支持、非透明或损坏文件

沿用 M1 预检错误：分别显示格式不支持、仅支持透明底、一次一张或解码失败；不出现越界入口。

#### E. 导出失败、像素校验失败或下载被阻止

1. 导出失败与下载被阻止沿用 M1：保留审校结果、可重试、提示允许下载。
2. 像素校验失败单独说明（有部位包含非原图像素），不生成半成品下载，引导返回审校后重试。

## 7. 明确不做（v3.0-alpha）

以下均不属于 v3.0-alpha：

- 遮挡补全：LaMa 本地档、BYOK SD 补全、"整体补齐/局部合成"双版本与切换 UI——属 v3.1。本版对 occluded 标记最多展示（P1），不做补全。
- 绑骨与动画：骨架模板自动挂接、预设动作库、姿势参数滑杆、关键帧编辑、蒙皮权重、IK、物理——属 v3.5，其中专业级编辑器能力属"永不"。
- 逐帧渲染序列/图集导出、Godot Skeleton2D 场景、Spine JSON、DragonBones JSON——属 v3.5（Pro 进阶选项）。
- 蒙版手刷工具——视 v3.0-alpha 黄金集对 SAM 质量的验证结果决定是否进 v3.1。
- 部位图集打包与 Phaser/Godot 格式的部位导出；引擎格式导出只在 M1 切帧工作区提供。
- 去底与 AI 抠图；生成图像或视频；视频输入。
- 多图批量、多角色同拆、多角度/三视图编排。
- 账号体系、云存储、服务器端处理、LLM 服务器代理（BYOK 直连，key 不经 SpriteFlow 服务器）。
- 3D、桌面版；移动端不是本版验收对象。

|---|---|---|
