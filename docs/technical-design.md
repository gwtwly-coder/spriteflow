# SpriteFlow 技术方案（工作代号）

> 定位：面向 2D 游戏（先瞄准 vibe coder / 网页小游戏人群）的「AI 生图 → 引擎就绪素材」纯前端管线。
> 核心能力：去背景 → 自动切帧 → 人工确认 → 合图集 → 多引擎导出。
> 约束：服务器成本趋近于零；单人可维护；商用品质。

---

## 1. 产品边界（第一版做什么，不做什么）

**做：**
- 输入：PNG / JPG / WebP 单图，GIF / APNG 动图，图生视频输出（MP4/WebM，v2 主功能），ZIP 图片包
- 输出：图集 PNG/WebP + 各引擎描述文件（Phaser / Godot / libGDX / Cocos / 通用 JSON）+ 帧序列 ZIP
- 核心流程：背景移除 → 帧检测 → 帧规范化 → 审校编辑 → 打包导出

**不做（明确砍掉）：**
- 3D 素材管线（GPU 成本 + 红海竞争）
- 生成能力本身（生图交给 ChatGPT/MJ，我们只做「AI 出图 → 引擎可用」的胶水）
- 服务端处理、用户素材存储（v1 连账号体系都可以没有）
- 骨骼动画编辑器（Spine 竞品是团队级数年工程；动画生成交给图生视频模型，本站只做「视频之后」的处理）

**产品原则（贯穿所有设计决策）：**
> 全自动切图是伪命题（Photoshop 和 TexturePacker 也不敢承诺）。
> 商用品质 = 强自动检测（做对 90%）+ 极低摩擦的人工确认（10 秒收尾）。
> 检测器拿不准时不许瞎切，必须显式降级并给用户一个合理默认的手动模式。

## 2. 总体架构

```

│                                                                                │
│  UI 层    React 19 + TypeScript + Vite                                         │
│           Zustand（状态）+ zundo（undo/redo）+ i18n（中英双语，第一天就做）      │
│                                                                                │
│  编辑器   Canvas2D 视口（pan/zoom，支持 8K 图）+ 帧框交互 + 动画预览时间轴      │
│                                                                                │
│  处理层   Web Worker × N（OffscreenCanvas + ArrayBuffer transfer，UI 永不卡）  │
│           ├─ 解码/编码：createImageBitmap、OffscreenCanvas.convertToBlob       │
│           ├─ 像素算法：flood-fill、连通域、投影分析、MaxRects（TS 实现）       │
│           ├─ WebCodecs 视频硬解（v2）+ ffmpeg.wasm 兜底（懒加载）：抽帧        │
│           └─ onnxruntime-web（懒加载）：AI 抠图模型，WebGPU 后端 + WASM 回退   │
│                                                                                │
│  资产     模型/ffmpeg 大文件放 Cloudflare R2，按功能触发时才下载               │
└────────────────────────────────────────────────────────────────────────────────┘
                                    │
                    Cloudflare Pages（静态托管，免费额度）
                                    │
              Lemon Squeezy（收款+License）→ 客户端功能门控
              （后期如需：1 个 CF Worker 做服务端 license 校验）
```

**关键决策与理由：**
- **纯前端处理**：用户文件不出浏览器。零算力成本、天然横向扩展、且「隐私安全」对海外用户是实打实的卖点。
- **Worker 化**：所有像素级操作（去底、连通域、打包）在 Worker 跑，主线程只做交互。商用品质的底线是 4K 图处理期间界面不冻结。
- **大依赖懒加载**：ffmpeg.wasm（~30MB）和 AI 抠图模型（5~170MB）绝不打进首屏包。首屏 JS 预算 < 300KB gzip。
- **Web 而非桌面**：获客摩擦最低、迭代最快。桌面版（Tauri，包体小）作为 Pro 权益在后期提供，不作为第一形态。

## 3. 切图引擎（核心难点）

### 3.1 设计思路：检测级联 + 置信度决策，而不是单一算法

真实世界的输入大致五类，每类最优策略不同：

| 输入类型 | 典型来源 | 特征 | 最优策略 |
|---|---|---|---|
| A. 透明底网格表 | 老素材包、已处理过的表 | 均匀网格，透明槽分隔 | 投影法找网格 |
| B. 不透明底网格表 | ChatGPT/MJ 直出、JPG | 白底/纯色底 | 先去底 → 投影法 |
| C. 散排/不规则打包 | TexturePacker 产物、拼贴画 | 透明底，位置无规律 | 连通域 |
| D. 单行动画条带 | 简单动画 | 一行多帧 | 投影法（一维） |
| E. 「叙事型」AI 图 | "character sheet" 式生成 | 帧大小不一、间距不齐、可能粘连 | 连通域 + 尺寸聚类 + 人工确认 |

引擎不要求用户声明类型，而是**依次尝试策略、按置信度选择**。

### 3.2 流水线各阶段

**Stage 0 — 输入归一化**
- `createImageBitmap` 解码（浏览器原生支持 PNG/JPG/WebP/BMP，含 EXIF 方向修正）
- GIF/APNG：ffmpeg.wasm 抽帧为位图序列
- 生成分析用降采样副本（最长边 ≤ 1024）用于快速探测，实际切割用原图

**Stage 1 — 背景移除（仅当输入不透明）**
- 判定：alpha 直方图中「完全不透明像素占比 > 99%」→ 视为不透明输入
- **L1 经典算法（v1 实现，覆盖 80% 场景，零依赖零延迟）：**
  1. 四边像素采样 → 颜色聚类 → 取边缘主导色为背景色候选
  2. 从图边缘 flood-fill（HSV 空间容差，容差自适应：背景色方差的函数）
  3. 形态学清理：开运算去噪点、闭运算补主体内误判孔洞
  4. 边缘 1~2px 羽化（alpha 渐变）+ 主体内孤岛保留判定
- **L2 AI 抠图（v1.5 引入，处理复杂/纹理背景）：**
  - onnxruntime-web 跑 ISNet-general-use（~40MB）或 u2netp（~5MB，快速档）
  - WebGPU 优先、WASM SIMD 回退；模型从 R2 按需下载并经 CacheAPI 长缓存
  - 两档设计：「快速」小模型默认，「高质量」大模型作为 Pro 功能

**Stage 2 — 帧检测（三策略级联）**

*策略 A：投影法（网格检测）*
1. alpha（或去底后 mask）做行列占用统计：`rowOcc[y] = 该行非透明像素数`
2. 占用信号低于阈值 → 判为 gutter（空槽）→ 得到候选切割线
3. 对占用信号做自相关求周期 → 候选 cell 尺寸（对 gutter 断续的脏图更鲁棒）
4. 网格验证：交叉验证切割线与周期一致性 → 输出置信度 0~1

*策略 B：连通域标记（CCL）*
- 两遍 + 并查集，8-连通，TS + Uint8Array 实现（4K 图 < 500ms，Worker 内可接受）
- 后处理：
  - 最小面积过滤（阈值 = 图面积 × 系数，可调）
  - **膨胀容差合并**：把 mask 膨胀 k px 后再跑 CCL，解决「帽子/武器和身体断开」被切碎的经典问题（k 默认取图短边的 1~2%）
  - 近邻 bbox 合并（间距 < 中位部件尺寸 × 系数）

*策略 C：尺寸聚类（动画帧分组）*
- 对所有 bbox 按宽高聚类（简单 k-means 或按中位数 ± 容差分桶）
- 用途：识别「哪些帧属于同一个实体的动画序列」；同一聚类的帧应用统一的规范化参数

*决策逻辑：*
```
if 策略A置信度 > 0.9:
    用网格切割；再对每个 cell 跑轻量 CCL
    └─ 若某 cell 内出现多个连通域 → 标记「粘连帧」（AI 常见病），转人工确认
else if 有效连通域数量 >= 2 且尺寸聚类轮廓清晰:
    用连通域结果
else:
    降级：手动网格模式（默认按平方根猜测行列数，用户拖两条滑杆定行列）
```

**Stage 3 — 帧规范化（对 AI 素材的特化，本产品差异化所在）**
- **Auto-trim**：每帧裁到内容 bbox + 可配置 padding
- **锚点对齐**：以「底边中点」或「质心」为锚统一帧位置——修正 AI 生成序列里角色上下跳动、大小忽变的问题（walk cycle 的救命功能）
- **尺寸归一**：帧尺寸相对聚类中位数偏差在 5%~30% 的，等比缩放对齐；偏差过大的不自动缩放（可能是误检）
- **重复帧检测**：dHash（64-bit 感知哈希）+ 汉明距离，距离 < 4 判为重复 → 默认折叠、用户可展开（AI 很爱重复输出同一帧）
- **离群帧标记**：尺寸/长宽比偏离聚类中位数 > 40% 的帧打「需复核」标签——AI 幻觉帧（画风突变、肢体畸变）无法被算法修复，但必须被算法**发现并标记**，这是体验的及格线
- **画布统一**：聚类内统一到最大 bbox，按锚点摆放

**Stage 4 — 检测参数实时可调**
- 容差 / 最小面积 / 膨胀半径 / 合并距离做成侧栏滑杆，调整后 300ms 防抖增量重算
- 增量策略：先在降采样副本上重算检测，用户停手后再对原图执行——保证滑杆跟手

### 3.3 「什么图都能切好」的诚实边界

必须向自己承认三件事，并转化为产品行为：
1. **内容性损坏不可修复**：AI 每帧画风都变、角色根本不是同一个——没有任何切图算法能救。产品行为：检测出聚类离群 → 明确标记 → 引导用户回炉重新生成，而不是硬切出垃圾帧让用户骂工具不行。
2. **模糊输入必须有人工兜底**：降级路径（手动网格 + 手动画框）不是二等功能，是一等功能，交互打磨标准和自动模式相同。
3. **承诺话术**：对外说「10 秒从 AI 图到引擎素材」，不说「全自动万能」。

## 3.5 视频转动画帧管线（v2 主功能）

> 定位：用户在 Kling / Vidu / Runway 等图生视频模型里让角色「演」出动作，本站负责视频之后的全部——产出的直接是引擎就绪的循环动画帧序列/图集。**模型无关**：任何来源的视频都能处理，这是对模型迭代风险的天然对冲。

真实痛点：一条 5 秒 1080p/30fps 视频 ≈ 150 帧，且带场景背景、角色漂移、色彩抖动；游戏需要的只是一套 8~16 帧的透明底循环动画。

### 3.5.1 解码与抽帧
- WebCodecs（VideoDecoder）+ mp4box.js / WebM demuxer：浏览器硬件解码，1080p 全量抽帧秒级完成，零依赖体积
- ffmpeg.wasm 兜底奇异容器格式（维持懒加载策略，首屏不碰）

### 3.5.2 逐帧抠像级联（质量决定成败）
- **L0 绿幕优先（质量上限最高）**：首帧边缘色聚类检测纯色/绿幕背景 → 全程 chroma key + 边缘去溢色（despill）。配套产品内容：**视频生成 prompt 模板库**（动作类型 × 视角 × `green screen background, static camera, full body` 等要素），引导用户在生成阶段就产出好处理的视频——把 prompt 经验产品化，免费送，是零成本差异化
- **L1 时序视频抠像**：RVM（Robust Video Matting）ONNX 版（mobilenetv3 backbone，几十 MB，WebGPU），无需绿幕，时序传播保证帧间蒙版稳定
- **L2 兜底**：首帧 SAM 蒙版 + 光流传播（轻量，质量一般，救急用）
- 三档自动选择，允许手动切换

### 3.5.3 智能抽帧（核心算法卖点）
- 降采样灰度帧差分 → 累积运动量曲线
- **沿运动曲线均匀取样，而非按时间取样**：动作忽快忽慢时仍得到节奏均匀的帧序列——这是「视频能当游戏动画用」的关键一步
- pHash 掐掉开头静止段（视频模型常见的定格酝酿）与重复帧
- 目标帧数可调（默认 12；像素风 6~8）

### 3.5.4 锚点稳定与规范化
- 逐帧 mask → bbox → 底边中点对齐 + 高度归一，消除视频模型固有的镜头漂移与角色游移
- 直接复用 3.4 的锚点对齐 / 尺寸归一 / 画布统一逻辑（管线递进红利）

### 3.5.5 色彩防闪烁
- 以参考帧（首帧或中位帧）做 LAB 色彩统计迁移（均值/方差对齐），缓解逐帧色彩抖动；目标「显著改善」而非完美

### 3.5.6 循环闭合与多段切分
- 循环检测：首帧与后续帧 pHash 距离最小的点作为闭合候选，标记在时间轴上
- 时间轴 UI：拖入出点，一条视频切出多套动画（idle / walk / attack），各自命名独立导出

### 3.5.7 BYOK 生成编排（远期可选）
- 站内用用户自己的 Kling / Runway / Vidu API key 直接发起生成：选模板（动作 × 视角 × 绿幕）→ 生成完自动进入后处理管线，全程无服务器成本（BYOK）
- 价值在「prompt 模板 + 全自动串联」，不在生成本身

## 4. 审校编辑器（商用品质的另一半）

自动检测负责 90%，剩下 10% 的体验决定用户留不留：

- **视口**：Canvas2D + 视口变换（pan/zoom/fit），8192×8192 图流畅浏览；帧框用矢量绘制层，选中新帧高亮 + 尺寸标注
- **帧操作**：拖动移动、8 手柄缩放、框合并、框拆分（两点拉线切割）、新增框、删除、帧排序拖拽
- **动画预览**：底部时间轴，帧序列实时播放，可调 FPS，**洋葱皮**（半透明前后帧叠加）——对齐动画时刚需
- **撤销/重做**：zundo，所有帧操作可回溯
- **快捷键**：与主流工具对齐（Aseprite/Photoshop 肌肉记忆），完整 keymap 文档
- **批量属性**：框选多帧 → 统一改 padding/锚点/缩放

## 5. 打包与导出

### 5.1 打包算法
- **MaxRects**（业界标准）：BSSF / BAF / BLSF 启发式可切换，支持 90° 旋转选项
- v1 直接用 `maxrects-packer`（MIT，质量可靠），性能不足再自研 Rust→WASM
- 细节功能（直接决定「导出能不能直接用」）：
  - sprite 间 padding（默认 2px）
  - **extrude 出血边**（边缘像素外扩 1px）——消除引擎渲染时的缝隙伪影，TexturePacker 的招牌细节，必须有
  - 输出尺寸：自动 / 强制 POT（2048/4096/8192）/ 上限约束
  - 8-bit 量化（jSquash/pngquant wasm）作为可选压缩

### 5.2 导出格式矩阵

| 目标 | 产物 | 实现要点 |
|---|---|---|
| Phaser 3 | atlas.png + JSONHash/JSONArray | 官方格式，Loader 直接吃，`pixels` 不需要 |
| Godot 4 | 帧序列 ZIP + 生成用 .gd 脚本；或 atlas + .tres | **优先做脚本方案**：ZIP 里放 frames/ + build_spriteframes.gd，用户拖进 Godot 跑一下自动建好 SpriteFrames 资源。比手写 .tres 抗版本变化。.tres 直出作为实验功能 |
| libGDX | atlas.png + .atlas 文本 | 纯文本格式，易生成 |
| Cocos | atlas.png + .plist | XML/plist，模板化生成 |
| Unity | 帧序列 ZIP（+ 实验性 .meta） | Unity 的 meta 随版本漂移，脆；帧序列 + Editor 脚本更稳 |
| 通用 | PNG 序列 / GIF 预览 / 自定义 JSON | GIF 用 gifenc（轻量） |
| WebP | 无损 WebP 图集 | 体积比 PNG 小 20-30%，Phaser/Godot 均支持 |

**打包成一键下载 ZIP**（fflate，快且小）。

## 6. 性能预算与工程实现

| 指标 | 预算 | 手段 |
|---|---|---|
| 首屏 JS | < 300KB gzip | 大依赖全部懒加载 |
| 4K 图连通域 | < 500ms | Worker + TypedArray；后续热点迁 Rust/WASM |
| 4K 图经典去底 | < 1s | flood-fill 线性扫描 |
| 4K 图 AI 去底 | < 3s（WebGPU）/ < 10s（WASM 回退） | 模型分级 |
| 打包 500 帧 | < 200ms | MaxRects + 增量重排 |
| 内存上限 | 8192² RGBA ≈ 268MB | 超限提示降采样选项；移动端默认限 4096 |

工程规范：
- **检测管线核心（Stage 0~3）写成与 DOM 无关的纯 TS 模块**（输入 ImageData，输出 Frame[]）——这是可测试性的前提，也是未来做 CLI / 桌面版 / API 复用的资产
- Worker 通信用 Comlink，处理进度回传（进度条必须真实，商用细节）
- 文件系统访问 API（Chrome）支持直接读写本地文件夹，批量模式用

## 7. 质量保障体系（demo 与商用的真正分水岭）

**黄金测试集（Golden Dataset）**：
- 目标 60+ 个真实样本，按 3.1 的五类输入覆盖，重点收集**带典型缺陷的 AI 直出图**（白底、帧粘连、间距不齐、重复帧、幻觉帧）
- 来源：自己用 ChatGPT/MJ 批量生成典型病例 + Reddit/社区里用户贴过的真实素材（注意授权）
- 每个样本附带期望结果标注（帧数、各帧 bbox 容差区间、期望降级行为）

**回归测试**：
- Node 环境（无头）直接跑纯 TS 检测管线（见第 6 节的模块化要求），对黄金集断言：帧数精确匹配、bbox IoU > 0.9、降级类样本触发正确的降级路径
- GitHub Actions CI，每次提交全量回归
- **用户反馈闭环**：界面常驻「这个结果不对？一键上报（仅上传图片，匿名）」按钮，坏例进黄金集——这是检测类产品持续变准的唯一正道

## 8. 商业化架构（第一天就埋好，但不过早建设）

- **免费**：核心切图 + 打包、PNG/Phaser/通用 JSON 导出、≤ 2048 图、无水印（水印伤害信任，不用）
- **Pro（一次性 $19~29 买断，早鸟定价策略）**：AI 高质量去底模型、全部引擎导出（Godot/libGDX/Cocos/Unity）、> 2048 图、批量队列、锚点对齐/尺寸归一等高级规范化、桌面版（后期）
- **授权**：Lemon Squeezy 发 License Key → 客户端功能门控。客户端校验可被破解——**现阶段接受**（个人工具被破解的损失 < 建设服务端校验的成本），后期量起来再加 CF Worker 服务端校验
- **隐私卖点**打在落地页第一屏：Your files never leave your browser

## 10. 技术风险清单

| 风险 | 应对 |
|---|---|
| 「万能切图」被用户理解为全自动万能 | 产品话术与降级 UX 双管齐下（见 3.3）；离群标记引导回炉 |
| WebGPU 覆盖率不足 | onnxruntime 自动回退 WASM SIMD；性能预算按回退档承诺 |
| ffmpeg.wasm 体积吓人 | 仅 GIF/视频功能触发时下载 + 强缓存；首屏不碰 |
| Godot .tres 格式随版本漂移 | 脚本方案为主（.gd 在用户侧执行，最抗变化） |
| 检测器在某些输入上静默失败 | 黄金集回归 + 上报闭环；置信度低必走显式降级，禁止静默乱切 |
| 单人维护战线过长 | 第 6 节模块化为未来复用留口；每阶段有明确退出标准，不追求一步到位 |
| 视频模型进化，未来可能原生输出透明底循环帧 | 定位「模型无关后处理 + 引擎导出」对冲：即便模型进步，抽帧节奏/锚点稳定/打包/引擎格式仍是本站职责；持续跟踪模型能力 |
| 逐帧抠像质量受视频质量制约 | 绿幕 prompt 模板引导 + RVM + 手动修补兜底；对外话术分层 |
| 150 帧级逐帧处理计算量 | WebCodecs 硬解 + Worker 池 + 增量处理；移动端限制视频时长 |

## 11. 工作流覆盖策略（提高使用频次与黏性）

### 11.1 开发者旅程与我们的位置

| 阶段 | 谁的地盘 | 我们的参与 |
|---|---|---|
| 创意/立项 | 自己 | 不碰 |
| 代码生成 | Cursor / Claude | 不做编辑器；做「导出即代码」衔接 |
| 素材生成 | ChatGPT / MJ / Suno / ElevenLabs | BYOK 编排 + prompt 模板库（top of funnel，v2 起逐步扩展为「素材工厂前台」） |
| **素材加工** | （空白地带） | **核心腹地：切图 / 去底 / 视频转帧（M1–v2）** |
| 素材打包 | TexturePacker 等 | 已覆盖；横向扩到音频 sprite、位图字体 |
| 进引擎 | 手写胶水代码（用户的痛） | **导出即代码 + 实机预览（M3.5）** |
| 项目管理 | 文件夹 | 本地优先工作区（OPFS，零服务器） |
| 发布 | itch.io / Poki | 明确不碰，别跟生态龙头打 |
| 运营/分析 | GameAnalytics 等 | 不碰（服务器成本 + 非刚需） |

### 11.2 黏性原则：出口即入口

不搞注册积分/社区等伪黏性。黏性来自工作流本身——**每个功能的产物，都是下一个功能的输入**：

```
切完角色帧 → 界面提示「生成它的动作视频」(视频管线)
    → 帧序列就绪 → 提示「配上脚步声/攻击音」(音频管线)
    → 素材齐了 → 提示「扔进模板场景预览」(实机预览)
    → 满意了 → 导出「图集 + 代码 + 音频」一体化包
    → 下一个角色/下一个项目 → 工作区里回来
```

用户第一次为切图而来，之后每个环节都不需要离开。

### 11.3 新增功能（按 ROI 排序）

1. **导出即代码**（M3.5）：每个导出附带 Phaser `preload` + `anims.create` 配置、Godot 加载脚本，复制粘贴即用。实现成本极低（模板生成），却把「一堆素材文件」升级为「能跑的游戏部件」——这是从工具到管线的质变。
2. **Phaser 实机预览**（M3.5）：站内嵌一个模板游戏场景（静态托管零成本），用户把切好的动画拖进去，角色立刻在平台上走起来、跳起来。「切得对不对」从看图猜变成当场验证；录屏就是核弹级传播素材。
3. **本地项目工作区**（M3.5）：OPFS/IndexedDB 存项目素材集合、命名规范、历史导出，一键重导出。留存抓手，零服务器成本；云同步日后可作付费点。
4. **音频管线**（v2.5）：Suno 生成的歌不会无缝循环——循环点检测 + 交叉淡化、响度归一、音效切片、howler.js audio sprite（音频版图集，架构与图片打包同构）。纯前端（ffmpeg.wasm + WebAudio）。「Suno → 游戏可用的 BGM」是无人覆盖的真痛点。
5. **Tileset / Tiled 导出**（v2.5）：网格检测直接复用，导出 Tiled .tsx / Godot TileSet / Phaser tilemap JSON。
6. **位图字体**（v2.5）：TTF → 带描边/阴影特效的位图字体 → BMFont .fnt + png，主流引擎通吃。引擎自带文本丑是全体独立开发者的共识。

### 11.4 明确不做

- 游戏托管/发布（itch.io 碾压级存在）
- 代码编辑器/AI 编程（Cursor 的地盘，且烧钱）
- 数据分析、账号社交体系（服务器成本 + 伪需求）
- 任何需要我们垫付 GPU 的功能（一律 BYOK）
